# 근거 기반 공공문서 변경 해석 모델 구축

## 1. 프로젝트 목표

이 프로젝트는 공공·업무 문서의 두 버전을 비교해, 달라진 문구를 나열하는 데서 그치지 않고 **무엇이 어떻게 바뀌었고 누구의 업무·권리·책임에 어떤 영향을 주는지**를 원문 근거와 함께 설명하는 한국어 소형 언어모델(SLM)을 만드는 일이다.

대상은 조항·표·문단으로 이루어진 공공문서다. 모델에는 문서 전체를 그대로 넣기보다, 변경 전후의 대응 블록·문서 구조 정보·기계적 diff를 넣는다. 답변은 다음 네 요소로 제한한다.

1. 변경 전후 원문 근거
2. 변경 유형(추가·삭제·수정·분리·통합·실질 변경 없음)
3. 영향 대상과 직접적인 실무 영향
4. 근거에서 벗어나지 않는 해석 및 확인 필요 사항

즉, 변경 사유를 단정하거나 문서 밖 지식을 덧붙이지 않는다. 사실과 해석을 나눠서, 사람이 다시 확인할 수 있는 변경 분석을 주는 것이 목표다.

## 2. 차별점과 학습 가치

### 2.1 문제의 차별점

기존 문서 AI는 한 문서의 요약, 질의응답, 요구사항 추출이나 제안서 생성을 주로 다룬다. 이 프로젝트는 같은 업무 맥락의 **두 문서를 연결**하고, 문단·표 행 단위의 변화가 의무 수준·적용 범위·기한·책임 주체에 어떤 의미가 있는지 설명한다는 점이 다르다.

특히 단순 문자열 diff를 정답으로 삼지 않는다. 예를 들어 “7일 전 공지”가 “30일 전 공지 및 개별 통지”로 바뀌면, 모델은 기간·의무의 강화와 사업자·이용자에게 미치는 직접 영향을 구분해 제시해야 한다. 반대로 번호 이동이나 동의어 교체처럼 의미가 바뀌지 않은 사례도 `실질 변경 없음`으로 학습한다.

### 2.2 이 프로젝트에서 검증할 학습 방식

핵심 가설은 큰 교사 모델이 만든 분석 예시를 SFT(예시 답변으로 모델을 미세조정하는 학습)로 익히면, 작은 모델도 새 문서에서 근거 중심의 변경 해석을 할 수 있다는 것이다. [Distilling Step-by-Step](https://aclanthology.org/2023.findings-acl.507/)은 교사 모델의 추론 근거를 추가 학습 신호로 사용해 작은 모델의 과제 성능을 높일 수 있음을 보였다. 다만 여기서는 긴 자유형 사고과정을 따라 하게 하지 않고, 사람이 원문과 바로 대조할 수 있는 결과만 학습시킨다.

`변경 근거 → 변화 유형 → 영향 대상 → 직접 영향 → 제한된 해석`

이 방식으로 다음 세 가지를 함께 학습하고 평가한다.

- **정렬 역량:** 1:1 수정뿐 아니라 1:N 분리, N:1 통합, 추가·삭제를 대응시킨다.
- **근거 충실성:** 모든 판단을 입력의 문단·표 행에 연결하고, 원문에 없는 사유는 추측하지 않는다.
- **실무적 설명:** 수치·기한·범위·책임 변화가 이용자, 사업자, 수탁자, 담당 기관에 주는 영향을 짧고 명확하게 설명한다.

## 3. 진행 계획

### 3.1 원천데이터 수집 및 검증

초기 원천은 공식 링크에서 실제 본문 또는 추출 가능한 파일을 확인한 문서만 쓴다. 이 문서는 별도의 내부 조사 자료를 전제로 하지 않는다. 현재 확인을 끝낸 범위는 아래와 같다.

> **자체 조사 요약 (2026-08-03)**
> 합성의 출발점으로 쓸 수 있는 원문은 표준약관 3종과 개인정보처리방침 3종, 총 6종이다. 실제로 신·구 버전을 연결해 본문 차이까지 확인한 것은 인사혁신처 개인정보처리방침 연속 10쌍이며, 이 10쌍은 모두 같은 문서 유형이다. 제안요청서·지원사업 공고 등은 원문 쌍을 충분히 검증하지 못했으므로 이번 8,000건 목표의 원천으로 계산하지 않았다.

| 구분 | 확보 문서 | 활용할 변경 패턴 |
| --- | --- | --- |
| 표준약관 | 공정위 신유형 상품권·온라인게임·모바일게임 표준약관 | 적용 범위, 고지, 이용 제한, 계약 해지, 유효기간, 환불, 책임 |
| 개인정보처리방침 | 국가기록원·인천광역시·외교부 개인정보처리방침 | 처리 목적, 위탁, 제3자 제공, 보유 기간, 권리 행사, 표 구조 |
| 실제 버전 pair | 인사혁신처 개인정보처리방침 연속 버전 10쌍 | HTML 파싱·정렬 회귀검증, negative 사례, 소형 평가셋 |

합성 원문은 문서 전문을 새로 쓰지 않고, 원래 조항·표 구조를 살린 채 바꿀 수 있는 블록만 수정한다. 실제 문서 쌍은 대량 학습 재료가 아니라, 파서와 정답이 제대로 동작하는지 확인하는 기준선으로 둔다. 이렇게 실제 문서의 편중과 출처 불확실성을 줄인다.

각 원문에는 공식 URL, 수집 시각, 파일 형식, 해시, 추출 결과를 남긴다. 실제 문서 쌍으로 채택하려면 양쪽 원문을 열 수 있어야 하고, 같은 기반 문서임을 보이는 연결 정보와 본문 diff까지 모두 확인한다.

### 3.2 합성데이터 변환 및 SFT 구성

목표는 약 **8,000건**의 instruction 데이터다. 한 문서의 같은 문장을 반복해서 바꾸는 방식이 아니라, 문서 유형·변경 블록·변경 강도·답변 관점을 조합해 만든다.

| 데이터 구성 | 목표 비중 | 내용 |
| --- | ---: | --- |
| 단일 변경 해석 | 45% | 조항·문단·표 행의 추가, 삭제, 수치·기한·범위·주체 변경 |
| 복합 변경 해석 | 30% | 여러 변경을 묶어 공통 주제와 우선순위를 설명 |
| 구조 변화 | 15% | 표 행 신설·삭제, 조항 분리·통합, 이동과 의미 변화의 구분 |
| negative·경계 사례 | 10% | 표현·번호·서식만 변한 사례, 근거가 부족해 판단을 유보해야 하는 사례 |

생성 단위는 짧은 블록, 중간 길이 문맥, 여러 변경이 들어간 장문 문서의 세 단계다. 교사 모델은 정해진 형식으로 답을 만들고, 생성 규칙·원문 근거·영향 대상을 함께 남긴다. 이후 규칙 검사와 표본 검수로 잘못된 변경, 과도한 해석, 템플릿 반복을 걸러낸다.

학습은 KORMo-10B를 기준으로 하고, 짧은 입력부터 시작해 8K·16K 혼합 길이로 넓혀 간다. 장문 지시 데이터와 길이 혼합·packing을 다룬 [LongAlign](https://arxiv.org/abs/2401.18058)을 참고하되, 처음부터 복잡한 장문 학습을 만들지는 않는다. 먼저 검증 가능한 문서 블록으로 시작한다. 비교 실험에서는 결과만 학습한 모델과 구조화 분석까지 학습한 모델을 나눠, 분석 절차를 학습한 효과가 있는지 확인한다.

## 4. 어려운 부분과 대응

### 4.1 Context window 제한

공공문서는 조항·별표·표가 길고, 한 변경의 의미가 멀리 떨어진 정의나 예외 조항에 걸쳐 있을 수 있다. 문서 전체를 항상 넣으면 GPU 메모리와 학습 시간이 늘고 중요한 근거가 묻힐 수 있다. 반대로 임의로 자르면 필요한 문맥이 사라진다. 모델이 선언한 최대 길이가 그 길이에서 안정적으로 추론할 수 있다는 뜻도 아니다. [RULER](https://arxiv.org/abs/2404.06654)는 긴 입력에서 단순 정보 검색을 통과한 모델도 복수 단서 추적·집계 과제에서는 성능이 크게 떨어질 수 있음을 보였다.

그래서 “무조건 장문 학습”으로 가지 않는다. 먼저 변경 블록에 상위 제목, 인접 조항, 참조되는 정의·예외 조항을 붙인다. 그다음 4K 기준선, 8K·16K 혼합 길이 SFT, 필요할 때만 장문 확장의 순서로 실험한다. 학습 배치는 길이별로 묶고, 서로 독립인 sample만 packing해 padding 낭비를 줄인다. 이 방식은 다양한 길이의 장문 SFT를 위한 packing·sorted batching을 제안한 [LongAlign](https://arxiv.org/abs/2401.18058)과도 맞닿아 있다. 메모리가 실제 병목일 때만 [FlashAttention](https://arxiv.org/abs/2205.14135)·gradient checkpointing 같은 최적화를 적용한다.

평가는 평균 점수 하나로 끝내지 않는다. 입력 길이(4K/8K/16K), 변경 위치(앞·중간·뒤), 필요한 근거의 거리(인접·원거리)를 나눠 측정한다. 이 결과로 모델이 실제로 쓸 수 있는 context 길이와, 장문 확장이 업무 분석 품질에 도움이 되는지를 판단한다.

### 4.2 합성데이터의 다양성과 현실성

원천이 6종이므로, 무제한 변형을 하면 문체와 규칙이 반복되고 교사 모델의 표현 습관을 학생 모델이 그대로 따라 할 수 있다. 합성 텍스트를 반복 학습하면 언어적 다양성이 줄 수 있다는 보고도 있다([The Curious Decline of Linguistic Diversity](https://arxiv.org/abs/2311.09807)). 그래서 “8,000건”은 단순한 양이 아니라, 서로 다른 판단 상황을 얼마나 담았는지로 관리해야 한다.

그래서 만들기 전에는 문서 유형·변경 유형·영향 대상·문맥 길이·난이도별 목표 수를 정하고, 만든 뒤에는 같은 규칙·표현·원문 블록의 중복을 뺀다. 기간·범위·의무·예외·책임 주체·표 구조처럼 해당 문서에서 자연스러운 패턴만 바꾸며, 원문 전체를 새로 쓰는 합성은 하지 않는다. 특히 negative 사례를 따로 유지해 “뭐든 의미 있는 변경”이라고 답하는 편향을 막는다.

품질 검수는 자동 검사와 사람 표본 검수로 나눠 한다. 자동 단계에서는 원문 근거가 있는지, 전후에 실제 차이가 있는지, 답변 형식이 완성됐는지, 중복인지 확인한다. 사람 검수에서는 변경 유형과 영향 해석이 근거에서 자연스럽게 이어지는지를 본다. 실제 인사혁신처 버전 쌍과 학습에서 빼 둔 평가셋은 합성 규칙만 외운 모델인지 확인하는 기준으로 쓴다.

### 4.3 근거 없는 의도 추론과 평가의 한계

문서 변경만으로 발행기관의 내부 의도를 확정할 수는 없다. 또 그럴듯한 긴 답변도 일부 사실만 원문에 근거하고 나머지는 추측일 수 있다. [FActScore](https://aclanthology.org/2023.emnlp-main.741/)가 긴 생성문을 작은 사실 단위로 쪼개 근거 여부를 평가한 이유도 이 문제 때문이다.

답변에서 관찰 가능한 사실, 직접 영향, 가능성 있는 해석을 분명히 나누고, 근거가 부족하면 확인 질문을 제시하게 한다. 평가는 단순 문장 유사도 대신 다음 네 기준을 쓴다.

- **근거 정확성:** 인용·요약한 변경이 원문과 일치하는가
- **해석 타당성:** 영향 설명이 바뀐 조건과 책임 주체에서 논리적으로 이어지는가
- **과대추론 통제:** 문서에 없는 변경 사유나 법적 효과를 확정적으로 말하지 않는가
- **실무 유용성:** 검토자에게 필요한 조치·확인 항목을 제시하는가

학습에서 빼 둔 같은 평가셋으로 프롬프트 기반 모델, 결과만 SFT한 모델, 구조화 분석 SFT 모델, 교사 모델을 이름 없이 비교한다. 평균 점수뿐 아니라 원문 근거가 빠진 답변 비율과 사람 평가자의 일치도도 기록한다. 문장이 자연스럽다는 이유로 근거 충실성이 낮은 답변을 놓치지 않기 위해서다.
