# 문서 길잡이

이 프로젝트를 설명하는 문서는 세 편입니다. 처음부터 모두 읽으실 필요는 없습니다. 알고 싶은 내용에 맞는 문서부터 읽으시면 됩니다.

낯선 프로젝트 용어는 `용어_길잡이.md`에서 찾으실 수 있습니다.

## 처음 읽는 순서

0. `용어_길잡이.md`
1. `원천데이터_선정_프로세스.md`
2. `학습데이터_생성_프로세스.md`
3. `선행연구_분석.md`

전체 흐름만 빠르게 파악하려면 1번 문서의 `Pair acceptance rule`과 2번 문서의 3-0절 `전체 흐름`을 먼저 읽어 보세요. 그다음 궁금한 부분만 찾아가시면 됩니다.

**작업을 이어 하려는 것이라면 `세션_브리프.md` 한 편이면 됩니다.** 위 세 편은 프로젝트를 처음 이해하려는 분을 위한 것이고, 브리프는 오늘 어디서 이어 하는지만 짧게 적은 문서입니다.

## 문서별 역할

### 1. 원천데이터 선정 프로세스

이 문서는 다음 질문에 답합니다.

- 어떤 기관의 어떤 문서를 원천데이터로 골랐는가?
- 이전판과 이후판을 같은 문서의 버전이라고 판단한 근거는 무엇인가?
- 문서쌍을 채택하거나 반려하는 기준은 무엇인가?
- 원문을 수집할 때 어떤 문제가 반복해서 생겼는가?

특히 `Pair acceptance rule`은 다른 두 문서를 읽기 전에 알아 둘 기준입니다. 원문 두 개를
확보했다고 바로 문서쌍이 되는 것이 아니라, 버전의 연결과 실제 변경까지 확인해야 합니다.

### 2. 학습데이터 생성 프로세스

이 문서는 다음 질문에 답합니다.

- 문서를 어떤 단위로 나누고 서로 대응시키는가?
- 의미 없는 문자 차이와 실질 변경을 어떻게 구분하는가?
- 변경 유형 라벨은 어떤 구조이며, 수정 건수는 어떻게 세는가?
- 학습 데이터를 만드는 두 역할은 각각 무엇을 입력받아 무엇을 내는가?
- 그 결과물을 어떤 항목으로 채점하고 어떻게 골라내는가?

2절은 원천의 차이를 라벨 체계로 나누는 과정, 3절은 그 체계로 합성 데이터를 뽑는
파이프라인입니다. **이 문서는 지금 확정된 설계만 적습니다.** 판본별로 무엇을 왜 바꿨는지는
각 역할 폴더의 `CHANGELOG.md`에, 아직 못 정한 것은 `TODO.md`에 있습니다.

### 3. 선행연구 분석

이 문서는 다음 질문에 답합니다.

- 큰 모델이 만든 설명을 학습데이터로 쓸 때 무엇을 조심해야 하는가?
- 문서 개정을 어떤 단위와 라벨로 해석하는 것이 타당한가?
- 긴 문서를 모델에 넣을 때 어떤 한계가 있는가?
- 생성된 설명을 원문 근거와 어떻게 대조해야 하는가?

이 문서는 관련 연구를 두루 소개하는 일반 문헌조사가 아닙니다. 현재 데이터 생성 방식에
영향을 준 연구와, 그 연구에서 실제로 가져온 판단만 정리합니다.
