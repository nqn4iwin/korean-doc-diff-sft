
목표 : 두 버전의 공공문서를 비교해 다음을 원문 근거와 함께 설명하는 SLM을 학습시킨다.

- 무엇이 추가·삭제·수정되었는가
- 변화가 적용 범위와 책임에 어떤 영향을 주는가
- 어떤 관계자가 영향을 받는가
- 문서만으로 판단할 수 없어 추가 확인이 필요한 내용은 무엇인가 (옵션)

## 1. 프로젝트 목표

### 1.1 해결하려는 문제

버전 차이가 나는 같은 문서를 비교하는 과정에는 의미적인 해석이 함께 붙어야 한다. 예를 들어,

```
[기존본] 선정된 당사자에게는 7일 전 공지가 이루어질 예정이다.
[개정본] 선정된 당사자에게는 30일 전 공지 및 개별 통보가 이루어질 예정이다.
```

위와 같은 수정사항을 단순히 "날짜에 변화가 있었다"만으로 설명하기에는 부족하다. 공지 준비 기간과 통지 의무가 강화됐고, 그 변경사항이 기관과 이용자 양쪽에 영향이 있다는 점까지 설명해야 한다. 반대로 아래와 같은 경우도 존재한다.

```
[기존본] 제 1조에 따르면 ...
[개정본] 1조. ...
```

이처럼 조항 번호 이동·줄바꿈·동의어 교체는 "실질 변경 없음"으로 구분되는 것이 마땅하다. 모든 차이를 중요한 변화로 해석하면 신뢰가 떨어진다. 그러나 이 두 구분은 추론능력을 요구하기 때문에 소규모 언어모델(SLM)에게 기대하기 어려운 수준의 능력이다. 따라서 이 점을 교사 모델의 추론 과정까지 증류받은 학생 모델을 학습시키는 것으로 해결해보고자 한다.

### 1.2 프로젝트 목표와 범위

학습 대상인 학생 모델 SLM(KORMo-10b)은 context 제한이 있으므로 문서 전체가 아니라 전처리를 거친 **변경 전후 블록·문서 구조·주변 문맥**을 입력받고, **원문 근거 / 변경 유형 / 영향 대상과 직접 영향 / 제한된 해석**을 출력한다. 실제 입출력 예시는 아래와 같다.

**입력**

```text
[이전판] mpm_privacyOld14-B0117
② 인사혁신처는 위탁계약 체결 시 「개인정보 보호법」제26조에 따라 … 재위탁 제한,
   수탁자에 대한 관리ㆍ감독, 손해배상 등 책임에 관한 사항을 계약서 등 문서에 명시하고 …

[최신판] mpm_privacyOld15-B0104, B0105
② (위와 동일)
③ 「개인정보 보호법」 제26조 제6항에 따라 수탁자가 당사의 개인정보 처리업무를
   재위탁하는 경우 인사혁신처의 동의를 받고 있습니다.
```

**출력**

```json
{
  "judgement": "positive",
  "labels": [
    {
      "대상": "절차·요건",
      "방향": "새로 생겼다",
      "근거": "(해당 조항 없음) → 「개인정보 보호법」 제26조 제6항에 따라 수탁자가 … 재위탁하는 경우 인사혁신처의 동의를 받고 있습니다"
    }
  ],
  "impacts": [
    { "주체": "수탁자", "영향": "재위탁 시 인사혁신처의 동의를 받아야 하는 의무가 생겼다" },
    { "주체": "인사혁신처", "영향": "수탁자의 재위탁을 통제할 권한이 생겼다" }
  ],
  "direct_impact": "수탁자는 재위탁 시 인사혁신처의 사전 동의를 받아야 하며, 위반 시 법적·계약적 책임을 질 수 있다. 인사혁신처는 재위탁 통제권을 확보해 개인정보 처리의 책임성을 강화할 수 있다."
}
```

`direct_impact`는 교사 모델이 실제로 생성한 문장이다. 기존 `재위탁 제한` 문구와 신설된 `동의` 조항의 차이를 구분하고, 영향 주체가 수탁자와 발주기관 양쪽임을 짚어야 한다. 이것이 요구하는 출력 수준이다. `judgement`와 `labels`의 어휘는 [[#2.2.4 변경 유형 라벨]]에서 정의한다.

**필드 순서가 곧 사고 순서다.** 언어모델은 앞에 쓴 것을 다시 읽어 다음을 정하므로, 출력 안에서 앞 필드가 뒤 필드의 입력이 된다. `impacts` 배열을 `direct_impact` 문장 앞에 둔 것은 모델이 문장을 쓸 때 자기가 방금 정리한 주체 목록을 보게 하려는 것이다. 순서를 바꾸면 이 설계가 무너진다.

**변경 위치(`changed_span`)는 모델에게 시키지 않는다.** 자기 신고가 실제 diff와 맞은 비율이 61%에 그쳤으므로, `source_data/classify_diff.py`가 기계로 계산한다.

| 포함 범위               | 제외 범위               |
| ------------------- | ------------------- |
| 공공문서의 두 버전 연결 및 비교  | 범용 파서 개발            |
| 문단·조항·표 행 단위의 변경 해석 | 변경 이유나 기관의 내적 의도 단정 |
| 근거 기반 SFT 데이터 구축    | 문서 전체의 자동 작성        |
| 소형 모델의 학습 효과 검증     | 초기 단계의 대규모 강화학습     |

### 1.3 차별점과 핵심가설

기존 문서 AI에 대한 연구/사례는 주로 한 문서에 대한 요약·질의응답·요구사항 추출을 다뤘다. 버전 차이가 나는 문서쌍을 분석하는 AI에 대한 연구도 [A Tale of Two Revisions](https://aclanthology.org/2024.findings-acl.190/), [ChangeSumm](https://aclanthology.org/2022.lrec-1.591/)처럼 개별 수정 설명과 문서 전체 변화 설명을 구분해 왔다. 본 프로젝트는 **버전 차이가 나는 두 문서를 연결하고, 변경점이 어떻게 해석되는지 설명한다는 점**에서 다르다. 그 점에서 본 프로젝트의 핵심 가설(영가설)은 다음과 같다.

> 교사 모델이 만든 구조화된 분석 사례를 SFT로 학습하면,
> 소형 모델도 처음 보는 문서에서 근거에 맞는 변경 해석을 생성할 수 있다.

이를 보장하듯 [Distilling Step-by-Step](https://aclanthology.org/2023.findings-acl.507/)은 큰 모델의 rationale을 추가 지도 신호로 쓰면 작은 모델의 추론 성능이 오름을 보였다. 다만 [Orca](https://aclanthology.org/2023.acl-long.830/)에서는 trace가 길어질수록 근거 없는 추론이 섞이므로, 사람이 원문과 대조할 수 있게 분석 순서를 제한해야 할 필요성을 지적했다.

## 2. 데이터 구축 전략

### 2.1 원천데이터 선정과 확보 현황

원천 데이터에 대한 선정 기준은 세 가지이다.

1. **공문서일 것**
   공식 출처에서 원문을 열 수 있고 출처·수집 시각·해시를 기록할 수 있어야 한다
2. **같은 기반 문서일 것**
   시행일·문서(과제)번호·공식 이전판 링크로 연결을 증명할 수 있어야 한다
3. **pair 안에 유의미한 차이가 최소 1건 이상 있을 것**
   무의미한 차이(위에서 본 `1조` ↔ `제 1조`)는 버리지 않고 'negative'로 보존한다

| 데이터 유형         | 데이터 예시                                                     | 상태 |
| -------------- | ---------------------------------------------------------- | -- |
| 개인정보처리방침       | 인사혁신처 내부적으로 매해 개정된 개인정보처리방침 (연속 버전 16개, 15쌍)               | 확정 |
| 표준약관           | 공정위 온라인게임·모바일게임·신유형 상품권 표준약관 (각각 약관번호 동일, 3쌍)              | 확정 |
| 제안요청서          | 한국마케팅진흥원 사전규격 ↔ 변경 입찰공고 (동일 과제번호 공유, 1쌍)                    | 확정 |
| 지원사업 공고·정정공고   | 중기부 팁스 공고 제2026-40호 ↔ 제2026-188호 (수정공고가 원공고 번호·일자를 본문에 인용, 1쌍) | 확정 |
| 기관 운영지침·사업시행지침 | 팁스 총괄 운영지침, 지역산업지원사업 공통운영요령, 중소기업기술개발 지원사업 운영요령, 해양수산 연구개발사업 운영규정 (각 문서 부칙의 시행일로 연결, 4쌍) | 확정 |

원천 데이터 수집 목표는 **pair 기준 30개**이며 현재 **24쌍**을 확보했다. 데이터 유형 5개를 모두 확보했으므로 유형별 5~6쌍으로 배분한다. 유형이 적을수록 특정 문체가 많아지기 때문에, **직접적인 pair를 많이 수집하기보다 유형을 다양하게 수집하는 것을 우선으로** 삼는다.

수집 과정에서 문서유형·변경지점·변경유형 세 축을 함께 고려하여 확보한다. 다만 인사혁신처 15쌍은 같은 문서의 연속 버전이라 독립 표본 15개가 아니라 하나의 문서 계열이며, [[#4.1 평가 데이터]]의 분할도 계열 단위로 한다. pair별 출처·해시·확인 수치는 `docs/원천데이터_선정_프로세스.md`에 기록한다.

### 2.2 학습용 합성 데이터 생성

목표는 30건의 원천데이터를 통한 6,000건의 학습용 합성 데이터 쌍을 구축하는 것이다.

#### 2.2.1 교사 모델의 적합성 판단

파이프라인 설계 전에 교사 모델의 능력을 측정하였다. **아래 표는 자체 GPU 서버에 올려 쓰던 시절의 교사 모델로 잰 값이다.** 모델이 바뀐 경위는 `training_data/설계_메모.md` 5절에 있다.

| 시킨 일                 |  표본 |                  결과 |
| -------------------- | --: | ------------------: |
| 문서 전체에서 변경점 찾기       | 10회 |                2/10 |
| 원본 문서 하나로 개정문 쓰기     | 36건 |               36/36 |
| 같은 지시로 서로 다른 변형 만들기  | 36건 |               35/36 |
| 자기가 무엇을 바꿨는지 위치 신고하기 | 36건 |               22/36 |
| 해석문 쓰기               |  6건 |                 6/6 |
| 변경 유형 라벨 판정하기        |  6건 |                 3/6 |
| 자기 답의 신뢰도 신고하기       |  6건 | 전부 `high` (틀린 답 포함) |

즉, 작성된 결과물에 대한 판단은 떨어지지만 데이터 합성 도구로써는 사용 가능한 결과가 나왔다.
따라서 합성데이터 생성 파이프라인 2단계에 모두 같은 교사 모델을 사용한다. **현재 교사 모델은 `solar-pro4-260806`이다.**

#### 2.2.2 합성 데이터 생성 파이프라인

**1단계. Solar 역할 B(쌍 만들기)**
	원천 데이터가 부족하기 때문에, 단일 문서 + 수정 유형을 입력받고 수정된 pair를 출력한다.

**2단계. Solar 역할 A(해석 붙이기)**
	추론을 학습하기 위해 단일 문서 + 수정 문서 쌍을 입력받고 차이에 대한 해석을 출력한다.
	단, B가 지시받은 수정 유형을 A에게 알려주지 않는다.
	(알려주면 direct_impact가 라벨 이름을 풀어 쓴 문장이 되어 6,000건이 같은 문체가 된다)

**3단계. 기계 대조**
	B가 지시받은 수정 유형과 A가 해석한 수정 유형이 동일한지 기계적으로 검수한다.
	동일하다면 B에서 A까지의 생성이 잘 작성된, 학습데이터 후보로 삼는다.
	동일하지 않아도 버리지 않는다. B가 엉뚱한 곳을 고친 경우는 드물고 대개 둘이 같은
	변경에 다른 이름을 붙인 것이므로, **A의 판정 라벨로 갈아끼워 그대로 쓴다.**
	서식 차이만 남은 산출은 negative로, 문장이 깨진 산출은 사람 확인으로 보낸다.
	폐기는 어느 쪽으로도 살릴 수 없는 것만이다. 버킷의 정의는 [[#2.3 데이터 품질 검수]]에 있다.

#### 2.2.3 최종 데이터셋 규모

원천 데이터만으로는 부족하기 때문에 합성으로 채운다. 원천 하나에서 여러 건이 나오는 근거는 세 축이다.

| 축                | 근거                                       |
| ---------------- | ---------------------------------------- |
| 조항당 적용 가능한 변경 유형 | 조항 하나에 걸 수 있는 `(대상, 방향)`이 여럿이다           |
| 유형당 변형 횟수        | 같은 지시를 반복해도 36건 중 35건이 서로 달랐다            |
| 문맥 길이 단계         | 짧은 블록 / 중간 문맥 / 복합 문맥                    |

다만 첫 축이 조항마다 다르므로 생성 전에 **조항별 적용 가능 변경 유형 표**를 만든다. 없으면 산출의 25~30%가 지시와 어긋나 버려진다. 수치가 없는 조항에 `수치·기준 / 늘었다`를 지시하면 모델은 시킬 수 없는 일을 못 하고 가장 가까운 다른 개정을 한다.

문맥은 세 단계로 둔다. 짧은 블록(조항·표 행 하나), 중간 문맥(상위 제목과 인접 조항 포함), 복합 문맥(여러 변경이 든 장문 구간)의 비율이 일정하게 출력되도록 한다.

| 데이터 유형 | 목표 비중 | 주요 내용 |
| --- | ---: | --- |
| 단일 변경 해석 | 45% | 추가·삭제, 수치·기한·범위·주체 변경 |
| 복합 변경 해석 | 30% | 여러 변경의 공통 주제와 영향 |
| 구조 변화 | 15% | 조항 분리·통합, 표 행 신설·삭제, 이동 |
| Negative·경계 사례 | 10% | 표현·번호·서식만 변경, 근거 부족 |

#### 2.2.4 변경 유형 라벨

라벨은 데이터 유형별로 나누지 않는다. [IteraTeR](https://aclanthology.org/2022.acl-long.250/)가 arXiv 초록·위키피디아·위키뉴스 세 종류에 하나의 체계를 그대로 적용하고 유형 차이를 출현 분포로 나타낸 방식을 따른다. 대신 라벨을 한 번에 고르게 하지 않고 세 단계로 나눠 묻는다.

| 단계 | 질문 | 선택지 |
| --- | --- | --- |
| 1단계 | 실질 변경인가 | negative / positive |
| 2단계 | 무엇이 바뀌었는가 | 기한·시점 / 수치·기준 / 적용 범위 / 수행 주체 / 절차·요건 / 제출물·기재사항 / 명칭 |
| 3단계 | 어떻게 바뀌었는가 | 늘었다 / 줄었다 / 다른 값 / 새로 생겼다 / 없어졌다 |

한 번에 묻지 않는 이유는 두 가지다. 첫째, 대상 7종과 방향 5종을 곱하면 35칸인데 실제 관측된 변경은 697건이라 칸당 20건꼴이 된다. IteraTeR에서 전체의 3.2%뿐이던 `Style` 라벨의 분류 F1이 0.13에 그쳤듯, 드문 라벨은 학습되지 않는다. 나눠 물으면 칸당 100건과 139건이 된다. 둘째, 모델이 틀렸을 때 실질 변경 여부를 못 가른 것인지 유형을 잘못 고른 것인지 분리해서 볼 수 있다.

두 축은 완전한 곱집합이 아니다. 조항에 자리가 없는 조합은 나오지 않기 때문이다. **어느 칸이 성립하는지는 미리 정하지 않고 실제로 관측된 것만 채운다.** 미리 정했다가 반례를 만난 적이 있다 — `명칭`에는 `늘었다`가 성립하지 않는다고 적어뒀는데 `전문기관은` → `전문기관 및 운영기관은`이 나왔다. 이렇게 채운 성립 여부 표가 [[#2.2.3 최종 데이터셋 규모]]의 조항별 적용 가능 변경 유형 표의 절반이 된다.

한 블록에 여러 변경이 겹치면 **개수를 제한하지 않고** `(대상, 방향, 근거)`의 목록으로 답한다. 같은 대상에 방향이 반대인 변경이 함께 든 사례가 나왔고, 그 둘을 구별하려면 어느 구간을 보고 그렇게 판정했는지를 적는 `근거`가 있어야 한다.

라벨을 붙이기 전에 기계가 먼저 거른다. 조항번호·항목기호·조항참조·붙임번호·목차페이지·따옴표기호·가운뎃점·띄어쓰기 여덟 가지 정규화 규칙을 적용해 전후가 같아지면 그 차이는 규칙 이름 그대로가 사유인 negative이므로 모델에 보내지 않는다. 규칙의 상세와 각 규칙이 잡아낸 실제 사례는 `docs/학습데이터_생성_프로세스.md`에 있다.

### 2.3 데이터 품질 검수

#### 개별 데이터셋 품질 검수 - rule base

- 유효한 JSON이고 스키마를 통과하는가?
- 변경 전후에 실제 차이가 존재하는가?
- 분류 용어가 본문에 노출되지 않았는가?
- 기계 diff로 재계산한 `changed_span`이 비어 있지 않은가?
- 인용한 근거 ID가 입력에 실제로 존재하는가?
- **B가 지시한 유형과 A가 판정한 유형이 일치하는가?**
	통과하면 학습 데이터로, 불일치하면 A의 판정 라벨로 교체하거나 폐기한다.
	서식 차이만 남은 산출은 폐기하지 않고 negative로 보낸다.

#### 전체 데이터셋 분포 검사

개별 데이터셋의 품질이 통과하여도, 역할 B가 산출해낸 100건 중 99건이 `제1조`를 `1조.`로 바꾼 표기 수정이면 전체 데이터셋의 분포가 부족하다. 따라서 데이터셋이 200건 생성될 때 마다 현재 변경 유형이 어디에 속하는지를 기준으로 분포 검사를 진행한다.

| 검사 축 | 상한 |
| --- | ---: |
| 단일 변경 유형의 비중 | 25% |
| Negative 비중 | 15% (목표 10%) |
| 단일 원천 조항에서 파생된 비중 | 2% |
| 최빈 변경 위치(`changed_span`) 패턴(날짜만·이름만·번호만)의 비중 | 20% |

중복 판정 키는 `(원천 조항 SHA-256, 변경 유형, 정규화한 changed_span)`이다.

#### 사람 표본 검수 (200건마다 10건)

변경 유형이 실제 차이와 일치하는지, 영향 설명이 바뀐 조건과 책임 주체에서 이어지는지, 문서에 없는 내용을 넣지 않았는지를 확인한다. 이는 합성 파이프라인이 확정되는 1,000건 까지 반복한다.

검수자 간 일치도는 100%를 목표로 두지 않는다. IteraTeR의 Fleiss' κ(여러 명이 같은 대상에 같은 라벨을 붙이는 정도를 우연 일치를 빼고 계산한 값)는 크라우드 작업자만으로 0.363, 전문 언어학자를 투입해도 0.501이었고, 불일치는 의미가 겹치는 라벨에 몰렸다. 정의서를 고쳐서 없앨 수 있는 종류가 아니므로 일치도는 없애야 할 오류가 아니라 기록할 수치로 다룬다.

## 3. 모델 학습 및 비교 실험

### 3.1 학습 모델

기본 모델은 KORMo-10B다. 선정 기준은 다음과 같다.

1. **Instruction tuning이 안 된 base 모델이다.**
2. **반복 학습에 적당한 크기다.**
3. **학습 과정이 투명하다.**

### 3.2 학습 방법

LoRA를 사용하여 어댑터 기반 PEFT 방식을 택한다. 구체적인 이유는 다음과 같다.

1. 학습 시도를 다양하게 돌리기 위해선 회당 비용이 낮아야 한다.
2. 저장공간도 마찬가지로, adapter 체크포인트는 수십 MB, Full FT는 회당 수십 GB다.
3. 학습 모델은 base 모델로 고정되기 때문에 비교 조건이 자동으로 통제된다.

**메모리:** bf16, gradient checkpointing(순전파 중간값을 저장하지 않고 역전파 때 재계산해 메모리를 아끼는 기법), packing을 기본으로 둔다. [FlashAttention](https://arxiv.org/abs/2205.14135)은 실제 병목이 확인된 뒤에 검토한다.

**문맥 길이:** 4K 기준선 → 8K·16K 혼합 SFT → 길이별 성능·비용 비교 → 효과가 확인될 때만 확장. 근거는 [RULER](https://arxiv.org/abs/2404.06654)다. 모델이 선언한 최대 길이가 그 길이에서 안정적으로 추론한다는 뜻이 아니며, 긴 입력에서 단순 검색은 통과해도 여러 단서를 추적·집계하는 과제는 크게 떨어진다. 변경 해석이 정확히 후자다. 그래서 문맥을 무작정 늘리는 대신 변경 블록에 상위 제목·인접 조항·참조 정의를 붙인다.

배치는 [LongAlign](https://arxiv.org/abs/2401.18058)을 따른다. 짧은 sample을 하나의 시퀀스로 이어 붙이는 packing과 길이가 비슷한 sample끼리 묶는 sorted batching으로 padding 낭비를 줄인다. 서로 독립적인 sample만 packing한다.

### 3.3 비교 실험

##### 축 1. 학습 방법론

학습 모델, 데이터 규모와 학습 조건을 같게 두고 무엇을 학습시키느냐만 바꾼다.

| 비교군        | 학습 내용                                 |
| ---------- | ------------------------------------- |
| 프롬프팅       | 학습 없음                                 |
| 구조화 없는 SFT | 최종 답변만                                |
| 구조화 분석 SFT | `근거 → 유형 → 영향 대상 → 직접 영향 → 제한된 해석` 전체 |
| 선호도 학습     | 좋은 답과 나쁜 답의 쌍                         |

##### 축 2. 데이터 구성 ablation

학습에 사용하는 데이터 구성을 조정하며 ablation study를 진행한다.

| 제거 대상        | 확인할 내용              |
| ------------ | ------------------- |
| Negative 사례  | 의미 없는 차이를 과대해석하는지   |
| 복합 변경 해석     | 여러 변경을 묶는 능력이 떨어지는지 |
| 구조 변화 사례     | 조항 분리·통합 대응을 놓치는지   |
| 제한된 해석·확인 사항 | 근거 없는 단정이 늘어나는지     |

##### 축 3. 모델 규모

KORMo-10B에서 제일 좋은 결과를 낸 학습방식과 데이터 구성을 가지고 [Qwen3.6-27B](https://huggingface.co/Qwen/Qwen3.6-27B)를 같은 방법으로 학습하여 규모에 의한 차이를 확인한다.

비교를 위한 기준선은 다음과 같이 설정한다.
- 베이스라인 : 제로샷 KORMo
- 희망 수준 : few-shot Qwen3.6-27B 초과
- 탑 라인 : 교사 모델 `solar-pro4-260806`

## 4. 평가 설계

### 4.1 평가 데이터

평가를 위한 데이터를 30건 추가 수집하여 진행한다.
이때 학습 데이터에 포함되지 않도록 원천 기준으로 별도의 데이터를 수집해야 한다.

| 평가셋      | 구성                | 확인할 내용            |
| -------- | ----------------- | ----------------- |
| 실제 문서    | 학습에 안 쓴 문서 계열 통째로 | 합성 규칙만 외운 모델인지    |
| 합성       | 정답키가 있는 주입 사례     | 유형별 세부 오류         |
| Negative | 표기·번호·서식만 바뀐 사례   | 의미 없는 차이를 과대해석하는지 |

결과는 평균 하나로 보고하지 않고 **입력 길이(4K/8K/16K), 변경 위치(앞/중간/뒤), 근거 거리(인접/원거리), 변경 복잡도(단일/복합/구조)** 로 나누어 기록한다.

### 4.2 평가 방법론

**1차 — 기계 지표** (심판 없이 문자열 비교로 계산)

| 지표             | 측정 방법                                        | 교사 모델 현재값 |
| -------------- | -------------------------------------------- | -------: |
| 출력 형식 준수율      | 스키마 통과 비율                                    |     100% |
| 어휘 준수율         | `대상` 7종·`방향` 5종 안의 말만 쓴 비율                   |     100% |
| 실질 변경 판정 정확도   | negative / positive가 사람 판정과 같은 비율            |     100% |
| 변경 유형 라벨 정확도   | `(대상, 방향)` 집합이 정답키와 정확히 같은 비율                |    54.2% |
| 영향 주체 포착률      | `impacts`가 정답 주체를 하나도 빠뜨리지 않은 비율             |    91.7% |
| 문장·배열 일치율      | `direct_impact`가 자기 `impacts`의 주체를 다 담은 비율   |    95.8% |
| 근거 구간 유효율      | `근거`에 적은 구간이 원문에 실제로 있는 비율                   |      미측정 |

교사 모델 값은 `solar-pro4-260806`에 역할 A v2.2를 튜닝 8항목 × 3회 = 24호출 돌려 잰 것이며, 24호출 전체를 놓고 센 값이다. 실행은 `training_data/interpret/runs/20260811T063643.321217Z__v2.2__tune/`이고, 각 항목의 채점 정의는 `training_data/interpret/rubric.md`에 있다.

`changed_span` 일치율은 지표에서 뺐다. 자기 신고가 실제 diff와 맞은 비율이 61%에 그쳐 모델에게 시키지 않기로 했고, 지금은 기계가 계산하므로 모델을 재는 값이 아니다.

교사 모델 수치가 이미 있으므로 학생 모델의 개선 폭을 바로 비교할 수 있다. 탐지 성능은 놓친 비율과 오탐 비율을 분리해 기록한다. 근거성은 [FActScore](https://aclanthology.org/2023.emnlp-main.741/)를 참고해 긴 답변을 작은 사실 단위로 나눈 뒤 각각의 근거 여부를 따로 확인한다.

**2차 — 정량평가 (DeepEval)** — 기본 제공 지표를 활용하되, 상당수가 내부적으로 언어모델 심판을 사용하므로 1차를 대체하지 않고 보완한다.

**3차 — 정성평가 (LLM as a Judge)** — 기준은 평가 데이터셋 구축하신 분들께 문의하여 확정 후 likert scale로 평가를 진행한다.

**성공 기준** — 답변이 길거나 자연스러워지는 것으로 판단하지 않는다. 구조화 분석 SFT가 구조화 없는 SFT보다 1차 기계 지표에서 일관되게 개선되어야 한다.
