**지금 확정된 설계만 적는다.** 원천의 차이를 어떤 체계로 나누고(2절), 그 체계로 합성
데이터를 어떻게 뽑는지(3절)다. 경위·실측·미결은 아래에 있다.

## 1. 원천데이터 정의하기

**`docs/원천데이터_선정_프로세스.md`로 옮겼다.** 절 번호는 코드 주석과 다른 문서가
`2-3절`·`3-0절` 식으로 가리키므로 그대로 둔다.

값 하나만 남긴다. **비교가 이뤄진 원천 24쌍에서 실질 변경 838묶음이 나왔고, 쌍당 실질
변경이 유형마다 열 배 넘게 차이난다**(운영지침 5쌍이 404묶음, 표준약관 3쌍이 4묶음).
그래서 표준약관·정정공고는 수량이 아니라 **유형 대표성** 확보용이다.

**838묶음 중 학습에 쓰는 것은 697묶음이다.** 나머지 141묶음은 2026-08-18에 채점용
홀드아웃으로 받은 산업기술혁신사업 공통 운영요령이라 씨앗으로도 학습으로도 안 쓴다.
그리고 **확보한 쌍은 25쌍인데 비교가 된 것은 24쌍이다** -- 제안요청서 1쌍은 양쪽이
PDF라 문단 단위로 잘라낼 수 없어 diff가 0건이다.

## 2. 원천데이터에서 수정 유형 나누기

라벨 체계는 실제 pair **20쌍 462건에서 귀납했다.** 그 뒤 3쌍이 더 들어왔지만 다시
귀납하지 않는다. 새 pair는 체계를 고치는 자리가 아니라 **출현 분포를 채우는 자리**다.

### 2-0. 전체 흐름

```
원문 2개 → 1단계 기계 전처리 → 2단계 기계 검수 ┬ (가) 기계 negative  : 여기서 끝
                                               │
                                               ├ (나) 모델 판정 대상 : 규칙 통과 블록쌍 ┐
                                               └ (다) 추가·삭제 블록 : 짝이 없음      ┴→ 3단계 모델 판정
```

1·2단계는 `source_data/classify_diff.py`가 한다. 집계의 근거는 화면 출력이 아니라
결과 파일 `<앞>__<뒤>.classify.json`이며, 양쪽 원문의 SHA-256이 들어 있다.

### 2-1. 1단계 — 기계 전처리

블록은 `.hwpx`가 `hp:p` 요소 하나(표는 셀 하나), `.html`이 `p`·`div`·`li`·`td`·`th`
·`tr`·`h1`~`h4`·`dt`·`dd`·`br`에서 끊은 줄, `.txt`가 줄 하나다. 수집 형식의
우선순위는 **HWPX > HWP(변환) > PDF**다 — PDF는 지면 좌표에 놓인 글자라 문단이라는
개념이 없다. 블록 이름 `privacyOld14-B0007`은 **추출기가 매긴 자리이지 인쇄된 조
번호가 아니다.**

정렬은 `difflib.SequenceMatcher`로 하고 구간 안에서 글자 유사도 0.55를 넘는 짝끼리
1:1로 붙인다. 못 찾으면 **문서 전체 범위로 한 번 더** 짝짓고(2단 짝짓기), 그래도
없으면 추가 또는 삭제다.

### 2-2. 2단계 — 기계 검수

각 규칙은 비의미 차이 한 종류를 지운다. 규칙 R을 적용해 앞뒤가 같아지면 그 차이는
**곧 R이므로** 모델의 판단이 필요 없다.

| 규칙 | 잡는 것 | 예 |
| --- | --- | --- |
| 조항번호 | 블록 맨 앞(제목 자리)의 조 번호 밀림 | `제18조 (이용제한)` → `제19조 (이용제한)` |
| 항목기호 | 문단 첫 머리의 번호·불릿 | `(1) 별도의 동의` → `별도의 동의` |
| 조항참조 | 문장 안에서 밀린 항목 인용 | `이 지침 9. 마.` → `9. 라.` |
| 붙임번호 | 붙임·별표·별지·별첨·서식 번호 | `<별첨2>` → `<별첨2-1>` |
| 목차페이지 | 목차 줄 끝의 쪽 번호 | `산정기준 30` → `산정기준 29` |
| 따옴표기호 | 따옴표·괄호류, 블록 전체를 감싼 `<>` `[]` | `“지급보증 등”` ↔ `'지급보증 등'` |
| 가운뎃점 | 가운뎃점 글자 변형 | `수집·이용` → `수집ㆍ이용` |
| 띄어쓰기 | 공백 전부 | `바. 1억원` → `바.1억원` |

**원칙은 하나다. 문서의 diff를 훼손해서는 안 된다.** 그래서 `조항번호`는 블록 맨
앞에만 걸고(문장 안의 `제25조` → `제26조`는 근거 조문을 고친 실질 변경이다), `<>`는
블록 전체를 감싼 경우에만 벗긴다(`기준 < 10억` → `기준 > 10억`이 사라지면 안 된다).
**지우는 쪽 오류가 넘기는 쪽 오류보다 나쁘다** — 넘긴 것은 모델이 보지만 지운 것은
아무도 못 본다.

**negative는 두 단위로 나눈다.** 규칙에 걸렸다는 말은 그 블록만 놓고 보면 변경이
없다는 뜻이지 문서에 변경이 없다는 뜻이 아니다. **문서 단위**는 문서 안 모든 변경이
기계 negative인지를, **수정 단위**는 블록쌍 하나를 본다. 기계 negative는 **걸린 블록의
원문까지 남긴다** — 규칙이 실질 변경을 잘못 지웠는지 읽어 봐야 하기 때문이다.

**학습용 negative 샘플은 기계 negative에서 뽑지 않는다.** 기계 negative는 2단계에서
걸러져 **추론할 때 모델에 안 가므로**, 거기서 뽑으면 실전에 없는 종류만 배운다. 실전의
negative는 문구 정비(`구분된 표` ↔ `구분한 표`)·어미·오탈자·표기 통일 같은 것들이고
**정규화 규칙으로 잡을 수 없다** — 어미를 지우는 규칙은 `제출한다`와 `제출된다`도 같게
만드는데 그것은 능동·수동이 바뀐 실질 변경이다.

### 2-3. 3단계 — 모델 판정

라벨은 한 번에 묻지 않고 3단으로 쪼갠다. **1단계** negative / positive → positive일
때만 **2단계** 무엇이 바뀌었나(대상 7종) → **3단계** 어떻게 바뀌었나(방향 5종).
**희소한 라벨은 학습되지 않고**(합치면 35칸이라 697건을 넣어도 절반 이상이 한 자릿수다,
`docs/선행연구_분석.md` 2절), 쪼개면 **어디서 틀렸는지 갈리기** 때문이다.

| 대상 7종 | 무엇이 바뀌면 이 유형인가 | 예 |
| --- | --- | --- |
| 기한·시점 | 날짜, 기간, 처리 기한, 시행일 | `신속하게 처리` → `10일이내 처리` |
| 수치·기준 | 금액, 비율, 개수, 등급, 인용 조문 번호 | `제3조, 제3조의2, 제4조` → `제3조` |
| 적용 범위 | 규정이 미치는 대상·경우의 폭 | `영상정보처리기기` → `고정형 영상정보처리기기` |
| 수행 주체 | 일을 하거나 책임지는 쪽 | `발행자 등은` → `발행자 등(제2호는 발행자)은` |
| 절차·요건 | 밟아야 할 단계나 갖춰야 할 조건 | `신속하게 조치` → `신분 확인 후 지체 없이 조치` |
| 제출물·기재사항 | 내야 하거나 적어야 하는 항목 | 위탁 현황 표에서 `점검 결과` 열 삭제 |
| 명칭 | 가리키는 이름·연락 지점. 가리켜지는 것은 그대로 | `관리수준 진단` → `보호수준 평가` |

**`명칭`은 전화번호·이메일·URL·주소를 포함한다.** `수행 주체`와 가르는 기준은
가리켜지는 대상이 그대로냐다 — `인재정책과` → `윤리정책과`는 부서라는 자리가
그대로라 `명칭`이고, 담당이 실제로 다른 부서로 넘어갔으면 `수행 주체`다.

| 방향 5종 | 언제 이 방향인가 |
| --- | --- |
| 늘었다 / 줄었다 | 대상의 폭·크기·개수가 커졌다 / 작아졌다 |
| 다른 값 | 다른 값으로 바뀌었다. 커지지도 작아지지도 않았다 |
| 새로 생겼다 | 개정 전 조항에 그 대상이 없었다 |
| 없어졌다 | 개정 후 조항에 그 대상이 남지 않았다 |

**`늘었다·줄었다`와 `새로 생겼다·없어졌다`는 개정 전 조항에 그 대상이 있었는지로
가른다.** 개정 전 문장만 읽으면 되므로 기계적이다 — `전문기관은` → `전문기관 및
운영기관은`은 개정 전에도 주체가 있었으므로 `수행 주체 / 늘었다`다. **라벨의 주어는
대상이지 바뀐 조각이 아니다** — 이를 놓치면 목록에 항목이 추가된 경우가 전부 `새로
생겼다`로 쏠린다. **긍정↔부정 전환은 `다른 값`**이고, **35칸 중 어느 칸이 성립하지
않는지는 미리 정하지 않는다.**

**겹침의 답은 `(대상, 방향, 근거)` 목록이다.** 개수 제한이 없고 같은 대상이 여러 번
나와도 된다 — 한 블록에 `적용 범위 / 줄었다`(`과실` → `중과실`)와 `적용 범위 /
늘었다`(요구 금지 항목 추가)가 함께 든 사례가 있다. 대상이 같고 방향이 반대인 두 줄이
나란히 있으면 어느 줄이 무엇을 가리키는지 읽을 수 없으므로 **`근거`는 블록쌍마다
하나가 아니라 `(대상, 방향)` 쌍마다 하나** 붙는다. 세는 단위는 그래도 안 바뀌어 위는
**1건에 라벨 2개**다.

### 2-4. 셈 규칙

| 세는 단위 | 규칙 |
| --- | --- |
| 기계 negative | 규칙 조합마다 1건. 조 번호 밀림이 14곳이면 1건 |
| 수정 단위 positive | 같은 치환을 한 블록끼리 묶어 1건. 이름이 12곳에서 같게 바뀌면 1건 |
| 추가·삭제 | 블록 하나마다 1건 |

한 문장에서 날짜와 시각이 함께 바뀌면 세는 단위가 블록쌍이므로 **1건**이다. 실질
변경과 번호 이동이 한 구간에 섞이면 **구간이 아니라 블록쌍마다 따로 판정한다.**

### 2-5. 데이터 유형별 적용 가능 여부

**라벨 체계는 데이터 유형별로 나누지 않는다.** 하나의 체계를 적용한 뒤 **출현 분포**로
유형 차이를 기록한다(`docs/선행연구_분석.md` 2절). 다만 **전처리는 유형별로 달라도
된다** — 이 구분은 라벨에만 적용된다. 정렬·짝짓기가 못 하는 것들은 `docs/PLAN.md`의
「알고 있으나 지금은 두는 한계」에 있다.

## 3. 합성 데이터 만들기

원천만으로는 학습 데이터가 안 된다. 학습에 쓸 실질 변경이 697묶음인데 목표가 6,000건이고
분포도 쏠려 있다. 그래서 **원천 조항에 없던 개정을 지어내 새 pair를 만들고**, 실제
pair는 합성의 씨앗과 평가 기준선으로 쓴다.

### 3-0. 전체 흐름

교사 모델 하나에 **두 가지 일**을 시킨다. 같은 모델이지만 받는 프롬프트가 다르고 서로가
한 일을 모른다. 현재 교사 모델은 `solar-pro4-260806`이다.

```
[씨앗] 실제 pair 블록쌍
  │
  역할 A          해석을 붙인다  →  이 중 몇 개를 사람이 골라 역할 B의 예시로 쓴다
  │
[생성] 원천 조항 하나 + 지시 (대상, 방향)
  │
  역할 B          그 변경이 일어난 개정문을 쓴다  →  원문과 짝지어 새 pair가 된다
  │
[검증] 역할 A(blind)   지시를 모르는 채로 해석한다  →  지시한 라벨을 짚었나 = BM5
  │
[분류] 기계 게이트 BM1~BM5 → 버킷 네 갈래   (BM7은 표시만 하고 갈래를 안 나눈다)
  │
[산출] 학습 레코드 = 새 pair + 역할 A의 해석
```

**마지막 줄이 중요하다.** 학습 데이터의 정답은 역할 B가 쓴 개정문이 아니라 **역할 A의
해석**이다. 역할 B는 해석할 거리를 만드는 쪽이다.

### 3-1. 두 역할은 같은 라벨 체계를 쓴다

2절의 대상 7종 × 방향 5종을 역할 B는 **지시로 받고** 역할 A는 **판정으로 낸다.** 같은
말이 입력에도 출력에도 쓰이므로 둘을 맞대어 검증할 수 있다.

**역할 B가 받은 지시를 역할 A에게 알려주지 않는다.** 알려주면 A의 `direct_impact`가
라벨 이름을 풀어 쓴 문장이 되어 6,000건이 같은 문체가 된다. 검증이 무의미해지는 것은
덤이다 — 답을 보고 답을 맞히는 셈이 된다.

### 3-2. 역할 A — 해석

| 입력 | 출력 | 판본 | 온도 |
| --- | --- | --- | --- |
| 블록쌍(개정 전·후) 하나 | 아래 네 필드 | v2.2 | 0.2 (판정은 흔들리면 안 된다) |

```json
{
  "judgement": "positive 또는 negative",
  "labels": [ { "대상": "...", "방향": "...", "근거": "바뀐 구간만 '이전 → 이후' 형태로" } ],
  "impacts": [ { "주체": "원문에 나오는 말", "영향": "그 쪽이 개정 전과 달라진 점" } ],
  "direct_impact": "impacts를 옮긴 문장"
}
```

**출력 필드 순서가 곧 사고 순서다.** 배열 둘이 문장 앞에 온다. 언어모델은 이미 쓴 것을
다시 읽어 다음을 정하므로(autoregressive, 자기회귀) **출력 안에서 앞 필드가 뒤 필드의
입력이 된다.** 호출은 한 번이고 순서를 바꾸면 무너진다(`training_data/설계_메모.md` 2절).
**`changed_span`은 모델에게 안 시킨다** — 자기신고가 실제 개정문을 재현한 비율이
61%라 기계로 계산한다.

한 호출당 아래 10개를 0 또는 1로 매긴다. 현재값은 튜닝 8건 × 3회 = 24호출 기준이다.

| # | 항목 | 1점인 경우 | 누가 | 현재 |
| --- | --- | --- | --- | ---: |
| AM1 | JSON 파싱 | 출력이 JSON 하나로 파싱된다 | 기계 | 100% |
| AM2 | 어휘 준수 | `대상` 7종·`방향` 5종 안의 말만 쓴다 | 기계 | 100% |
| AM3 | 중복 없음 | 같은 `(대상, 방향)` 쌍이 두 번 안 나온다 | 기계 | 100% |
| AM4 | judgement 일치 | positive/negative가 사람 판정과 같다 | 기계 | 100% |
| AM5 | 라벨 일치 | `(대상, 방향)` 집합이 사람 라벨과 **정확히** 같다 | 기계 | 54.2% |
| AM6 | negative 처리 | negative일 때 `impacts`와 `direct_impact`가 비어 있다 | 기계 | 100% |
| AM7 | 영향 주체 | `impacts`가 정답 주체를 **다 담았다** | 기계 | 91.7% |
| AM8 | 문장·배열 일치 | `direct_impact`가 자기 `impacts`의 주체를 안 빠뜨렸다 | 기계 | 95.8% |
| AM9 | 근거 방향 | `근거`의 `이전 → 이후`를 뒤집어 적지 않았다 | 기계 | 100% |
| AH1 | 재진술 아님 | 조항을 다시 쓴 게 아니라 **누가 어떻게 되는지**를 썼다 | 사람 | 93.3% |

- **AM5는 게이트가 아니고 부분 점수도 없다.** 라벨 정확도가 중요한 쪽은 그 라벨을
  지시로 받는 역할 B이고, 거기서 BM5의 기준이 된다.
- **AM7은 반대로 포함 관계로만 본다.** 정답 주체는 "반드시 있어야 하는 최소 목록"이라,
  완전한 목록으로 쓰면 우리가 못 본 주체를 모델이 짚었을 때 벌을 주게 된다.
- **AH1은 positive 항목에서만 매긴다.** negative는 `direct_impact`가 비어 있는 것이
  정답이라 재진술할 문장이 없다. **앞에 기계 선별기가 있다** — 개정 후 원문과의 문자
  유사도가 0.60 이상이면 사람이 안 읽고 0점이다. 합격 판정이 아니라 걸러내기이며 짧은
  블록에서 오탐을 낸다.

### 3-3. 역할 B — 생성

| 입력 | 출력 | 판본 | 온도 |
| --- | --- | --- | --- |
| 원천 조항 하나 + `(대상, 방향)` + 그 쌍의 판정 기준 | `{"after": "개정된 조항 전문"}` | v1.2 | 0.9 |

온도가 높은 것은 같은 조합을 여러 번 돌릴 때 서로 달라야 표본이 늘기 때문이다.

**이름만 주면 안 된다.** 각 축의 정의와 판정 기준을 함께 주고 **실제 개정 사례를 예시로
넣는다. 예시에 대해서는 두 역할의 결론이 반대다** — 역할 A에서는 예시 문구 하나가 영향
칸 45개 중 39개를 같은 틀로 만들어 해로웠는데, 역할 B에서 예시를 뺐더니 BM5가 17%로
무너졌다. **역할 B에서 예시는 문체가 아니라 "조항에서 그 대상이 어디인지 찾는 법"을
가르치기 때문이다.** 지금은 예시를 넷 넣되 **한 축에 서로 다른 표면형 둘**을 둔다 —
베낄 단일 정답이 없으면 자리를 찾는 방식만 남는다.

**조항마다 걸 수 있는 지시가 다르다.** 수치가 없는 조항에 `(수치·기준, 다른 값)`을
시키면 모델은 가장 가까운 다른 개정을 하고 역할 A는 그것을 정확히 짚는다 — **양쪽 다
옳게 동작했고 지시가 틀린 것이다.** `generate.py`가 정규식 표층 판정으로 자리를 고른다:
주체 표기가 있으면 `수행 주체`, 서술어가 있으면 `절차·요건`, 숫자가 있으면 `수치·기준`,
정의·목적 조항에는 `(적용 범위, 늘었다)`만.

### 3-4. 왕복 검증 — 정답이 하나가 아니기 때문에

역할 B의 산출은 문자열 대조로 채점할 수 없다. **"이 조항에 이 변경을 넣은 개정문"은
여럿이기 때문이다.** 그래서 B가 쓴 개정문을 원문과 짝지어 역할 A에게 blind로 넣고, A가
지시받은 `(대상, 방향)`을 짚는지로 판정한다(BM5). 완전일치가 아니라 **포함**으로 본다
— 한 군데를 고쳐도 두 성격을 함께 띠는 일이 흔하다.

**BM5는 품질 게이트가 아니라 라벨 정합성 검사다.** 불일치하면 A의 판정 라벨로 갈아
끼우므로(`docs/기획서_최종.md` 2.3절) **실패해도 데이터는 남고 라벨만 갈린다.** 교사
라벨은 정답일 필요가 없다 — rationale의 쓸모는 정확도가 아니라 **학생이 따라갈 수 있는
일관된 경로**에 있다(`docs/선행연구_분석.md` 1절). **다만 상한이 있다** — A가 회수하지
못하는 라벨은 B가 아무리 잘 써도 통과할 수 없어, **B의 지시 어휘는 A가 회수하는 쌍부터
연다.**

### 3-5. 게이트와 버킷

| # | 항목 | 1점인 경우 | 누가 | 버킷 | 현재 |
| --- | --- | --- | --- | --- | ---: |
| BM1 | JSON 파싱 | 출력이 JSON 하나로 파싱된다 | 기계 | **예** | 100% |
| BM2 | 실제로 달라졌나 | 원문과 다르고 정규화 규칙(2-2절)에 안 걸린다 | 기계 | **예** | 100% |
| BM3 | 용어 비노출 | 분류 어휘가 개정문 본문에 안 샜다 | 기계 | **예** | 100% |
| BM4 | 국소 수정 | 조항 전체를 새로 쓰지 않았다 | 기계 | **예** | 100% |
| BM5a | 왕복 검증 (대상만) | 역할 A가 지시받은 `대상`을 짚었다 | 모델 | 아니오 | — |
| BM5 | 왕복 검증 | 역할 A가 지시받은 `(대상, 방향)`을 짚었다 | 모델 | **예** | 78.3% |
| BM6 | 변형 다양성 | 같은 조합 3회가 서로 다른 개정문이다 | 기계 | 아니오 | — |
| BM7 | 문장 검사 | 비문·지어냄·참조 깨짐으로 의심되는 곳이 없다 | 기계 | 아니오 | 81.7% |
| BH1 | 비합리 없음 | 말이 안 되는 문장이 아니다 | 사람 | 아니오 | 85% |

**BM5a를 따로 두는 이유** — 대상을 짚는 일과 방향을 정하는 일은 다른 능력이라, 한
칸으로 재면 둘이 서로 지워 "변화 없음"으로 보인다.

**BH1은 "비합리 없음"만 본다. 문체는 재지 않는다.** 채점자 간 일치도에서 **"말이 안
된다"는 합의가 되고 "개정문답다"는 안 되기** 때문이다.

**BM7은 하드 게이트가 아니라 표시다.** 걸린 것은 기록에 남겨 **읽을 순서를 정하는 데**
쓰고 빼내거나 버리지 않는다. `text_check.py`가 규칙 넷으로 매긴다.

| | 무엇을 보나 |
| --- | --- |
| C1 | 주체를 접속해 놓고 주격·주제 조사로 닫지 않았다 |
| C2 | 새로 세운 주체가 문서 어디에도 없다 |
| C3 | 새 수치가 문서 어디에도 없다 (`수치·기준`·`기한·시점` 지시는 예외) |
| C4 | 다른 조항을 받는 조항에서 주체를 통째로 갈았다 |

**C4가 따로 있는 것은 어휘 대조만으로 부족해서다.** `5급 이상 공무원`은 `5급`이 문서에
있어 C2에 안 걸린다 — 지어낸 것은 낱말이 아니라 **조합**이고, 진짜 문제는 `제1항에
따라`로 받는 주체를 갈아치워 앞 조항과 어긋난 것이다.

| 버킷 | 조건 | 어떻게 쓰나 |
| --- | --- | --- |
| 학습 후보 | BM1~BM5를 다 통과 | 사람 검수를 거쳐 학습 데이터로 |
| 라벨 교체 후보 | BM5만 실패 | 역할 A가 준 라벨로 갈아끼워 그대로 쓴다 |
| negative | 서식 차이만 남음 | 기획서가 요구한 negative 비중을 여기서 채운다 |
| 폐기 | 출력이 비었거나 파싱 실패 | 버린다 |

**버려지는 것이 거의 없다.** 실패해도 라벨을 갈거나 사람이 보면 살아난다.
