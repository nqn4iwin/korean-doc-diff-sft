# Literature Review

이 문서는 공공·업무 문서의 실제 변경을 근거와 함께 해석하는 SFT 프로젝트에 직접
참고한 연구만 남긴 요약이다. 각 연구의 결론을 그대로 적용하지 않고, 이 프로젝트의
데이터·평가 설계에 필요한 부분만 사용한다.

## 1. Teacher-to-student distillation

### Distilling Step-by-Step

[Distilling Step-by-Step](https://aclanthology.org/2023.findings-acl.507/)은 큰 모델이
만든 rationale을 추가 지도 신호로 사용해 작은 모델의 과제 성능을 높이는 방법을
보였다. 여기서 가져갈 점은 “답만” 학습하기보다 판단에 필요한 중간 산출물을 함께
학습한다는 것이다.

이 프로젝트에서는 숨겨진 사고과정을 복제하지 않는다. 대신 사람이 원문과 대조할 수
있는 `근거 → 변경 유형 → 영향 대상 → 직접 영향 → 제한된 해석`만 정답으로 만든다.

### Orca와 설명 trace의 한계

[Orca](https://aclanthology.org/2023.acl-long.830/)는 복잡한 설명 trace와 지시를
이용한 distillation을 제안했다. 다만 공문서 분석에서는 설명이 길어질수록 근거 없는
의도 추론이 섞일 위험이 있다. 따라서 교사 출력도 블록 ID와 전후 문장으로 검증할 수
있는 구조화 형식으로 제한한다.

## 2. Document revision interpretation

### Edit 단위와 주제 단위의 분리

[A Tale of Two Revisions](https://aclanthology.org/2024.findings-acl.190/)과
[ChangeSumm](https://aclanthology.org/2022.lrec-1.591/) 계열은 문서의 수정 하나를
설명하는 일과, 여러 수정을 묶어 문서 전체의 변화 방향을 설명하는 일을 구분한다.

프로젝트도 먼저 문단·조항·표 행의 실제 변경을 별도 atom으로 기록한다. 여러 변경을
하나의 “발주 의도”로 묶는 것은 후속 단계이며, 원문만으로 확정할 수 없는 경우에는
가능한 해석 또는 확인 질문으로 남긴다.

### 라벨 체계는 문서 유형별로 나누지 않는다

[IteraTeR](https://aclanthology.org/2022.acl-long.250/)는 arXiv 논문 초록, 위키피디아,
위키뉴스 세 종류 문서에 **하나의 수정 의도 라벨 체계를 그대로 적용**했다. 문서 유형별로
다른 라벨을 만들지 않고, 유형 차이는 같은 라벨의 **출현 분포**로 나타냈다. arXiv는 저자가
결과를 갱신하므로 의미 변화가 많고, 위키뉴스는 문법 교정에 몰린다는 식이다.

이 프로젝트도 같은 방식을 택한다. 개인정보처리방침·표준약관·제안요청서·공고·운영지침에
각각 다른 라벨을 두지 않고, 하나의 체계를 적용한 뒤 분포로 유형 차이를 기록한다.

가져갈 것은 **2단 구조**다. IteraTeR는 의미가 바뀐 수정(Meaning-Changed, 22.3%)과 바뀌지
않은 수정을 먼저 가르고, 후자를 Fluency·Coherence·Clarity·Style로 나눈다. 위층의 이 구분은
`실질 변경 없음`을 분리해야 하는 이 프로젝트의 요구와 정확히 겹친다. 반면 아래층 4종은
글쓰기 품질 기준이라 공문서에는 맞지 않는다. 조 번호가 한 칸 밀린 것은 문법 교정도 문장
다듬기도 아니다. 위층은 그대로 쓰고 아래층은 새로 정의한다.

### 라벨 일치도는 완전 일치를 목표로 두지 않는다

IteraTeR의 Fleiss' κ(여러 명이 같은 대상에 같은 라벨을 붙이는 정도를 우연 일치를 빼고
계산한 값)는 크라우드 작업자만으로 0.363, 전문 언어학자를 투입해 0.501이었다. 논문은
이를 보통 수준의 일치라고 부른다.

불일치는 의미가 겹치는 라벨에 몰렸다. Coherence로 붙은 393건 중 312건이 합의에 실패했고,
그중 68.8%가 Clarity에 표가 갈렸다. `synthetic_generation/blind_probe/`에서 관찰한
`scope_expanded` ↔ `scope_reduced` 겹침과 같은 성격의 문제이며, 정의서를 고쳐서 없앨 수
있는 종류가 아니다.

따라서 라벨 일치도의 목표를 100%로 두지 않는다. 대신 IteraTeR의 완화 장치를 가져온다.
가장 많이 혼동되는 두 라벨을 하나의 선택지로 합쳐 먼저 고르게 하고, 그 뒤에 갈라내는
질문을 하나 더 던지는 방식이다. 이들은 Clarity와 Style을 `Rephrasing` 한 칸으로 합친 뒤
명확성 개선 여부를 되물어, 파일럿 다섯 가지 중 가장 높은 일치도를 얻었다.

한 가지 더, 드물고 겹치는 라벨은 학습되지 않는다. 이들의 자동 분류기 F1은 Fluency 0.80,
Clarity 0.69인 반면 Coherence 0.32, 전체의 3.2%뿐이던 Style은 0.13이었다. 라벨 개수를
정할 때 각 라벨에 몇 건이 배정될지를 함께 본다.

### 정렬은 모델 이전 단계의 문제

[Re3](https://aclanthology.org/2024.acl-long.255/)와 요구사항 traceability 연구는
관련 단위를 먼저 연결하는 일이 중요함을 보여준다. 따라서 문자열 diff만으로
1:1, 1:N, N:1, 추가·삭제를 확정하지 않는다. 제목·조항·표의 구조와 실제 전후
본문을 함께 보존한 뒤 모델에 제공한다.

## 3. Long-context SFT

### 선언 길이와 실효 길이는 다르다

[RULER](https://arxiv.org/abs/2404.06654)는 긴 입력에서 단순 검색을 통과한 모델도
복수 단서 추적·집계에서는 성능이 떨어질 수 있음을 보여준다. 그래서 이 프로젝트는
문서 전체를 무조건 넣지 않는다. 변경 블록에 상위 제목, 인접 조항, 참조 정의·예외
조항을 붙여 필요한 문맥을 먼저 만든다.

### 단계적 길이 확장

[LongAlign](https://arxiv.org/abs/2401.18058)은 장문 지시 데이터, 길이 혼합,
packing과 sorted batching을 함께 다룬다. 프로젝트는 4K 기준선에서 시작해
8K·16K 혼합 길이로 확장하고, 길이·변경 위치·근거 거리를 나눈 평가에서 효과가
확인될 때만 더 긴 문맥을 사용한다.

메모리 병목이 확인된 경우에는 [FlashAttention](https://arxiv.org/abs/2205.14135)을
검토할 수 있지만, 데이터 구조와 평가보다 먼저 최적화를 추가하지 않는다.

## 4. Evidence-grounded evaluation

[FActScore](https://aclanthology.org/2023.emnlp-main.741/)는 장문 생성문을 작은
사실 단위로 나누어 근거 여부를 평가한다. 이 프로젝트도 문장 유사도보다 다음을
우선한다.

- 전후 원문과 인용한 변경이 일치하는가
- 변경 유형과 직접 영향이 해당 조건·주체에서 이어지는가
- 문서에 없는 사유나 법적 효과를 단정하지 않는가
- 실제 검토자가 확인할 수 있는 조치·질문을 남기는가

실제 pair는 학습 데이터와 분리해 평가에도 보존한다. 생성된 예시의 문장 품질이
원문 근거의 정확성을 가리지 않도록, 근거 누락 비율과 사람 검수 일치도도 함께
기록한다.
