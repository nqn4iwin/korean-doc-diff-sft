# 세션 브리프

**세션을 시작할 때 이것만 읽는다.** 자기 역할 절과 아래 「공통」만 보면 되고, 다른
역할 절은 안 읽어도 된다. 더 필요할 때만 각 절이 가리키는 문서로 내려간다.

이 문서는 **오늘 어디서 이어 하는지**를 적는다. 설계는 `학습데이터_생성_프로세스.md`,
경위는 각 역할의 `CHANGELOG.md`, 할 일 목록은 `TODO.md`에 있다.

---

## 공통

**무엇을 만드는가** — 공공·업무 문서의 개정 전후 블록쌍을 받아 **무엇이 어떻게 바뀌었고
누가 영향을 받는지**를 해석하는 SFT 데이터. 학습은 별도 저장소 `model_train`이 맡는다.

| | |
| --- | --- |
| 교사 모델 | `solar-pro4-260806` (업스테이지 공개 API). **`reasoning_effort`를 끄지 않는다** — 끄면 negative 판정이 무너진다 |
| 라벨 체계 | 대상 7종 × 방향 5종, 3단 판정. **잠갔다.** 새 pair는 체계를 고치는 자리가 아니라 출현 분포를 채우는 자리 |
| 합성 목표 | 6,000건. 필요 생성량은 6,000~7,000건 (옛 "2만 건"은 옛 모델 기준이라 폐기) |
| 원천 | 24쌍, 실질 변경 697건 |
| 학습 데이터의 정답 | **역할 A의 해석이다.** 역할 B가 쓴 개정문이 아니다 |

**Git은 `git.exe`로 실행한다.** WSL의 `git`은 줄바꿈 차이 때문에 멀쩡한 파일 수십 개를
수정된 것으로 잡고 작성자 이름도 안 남는다. 검색도 `git.exe grep`을 쓴다.

### 파일 소유 — 겹치면 커밋이 엉킨다

| 누가 | 무엇을 |
| --- | --- |
| **역할 A 세션** | `training_data/interpret/`, `docs/`, `진행상황.html`, `source_data/` |
| **역할 B 세션** | `training_data/mutate/`, `source_data/block_components.py` |

`docs/`는 역할 A 세션이 쥔다. **역할 B의 결과는 넘겨받아 반영한다** — 옆 세션이 이
문서들의 옛 수치를 믿고 갔다가 한 번 틀렸다. 수치를 인용하기 전에 어느 실행에서 나온
것인지 확인한다.

## 역할 A 세션 — 해석

블록쌍을 받아 `judgement` / `labels` / `impacts` / `direct_impact` 넷을 낸다.
설계는 `docs/학습데이터_생성_프로세스.md` 3-2절.

**지금 상태**

| | |
| --- | --- |
| 프롬프트 | v2.2 (2026-08-10에 잠금). 온도 0.2 |
| 채점 | AM1~AM4·AM6 100% / AM5 54.2% / AM7 91.7% / AM8 95.8% / AH1 93.3% (튜닝 24호출) |
| 나간 것 | 실질 변경 697건에 해석을 붙여 학습 레코드 605건을 뽑았고 1차 학습이 끝났다 |
| 도구 | `annotate.py`(배치 해석) · `export.py`(학습 레코드) · `run.py`(평가 세트 채점) |

**A-1은 끝났고 A-2가 남았다.** A-1은 "역할 B에게 줄 few-shot 예시 만들기"였고 검증됐다.
A-2는 "역할 B가 지어낸 합성 pair 6,000건에 해석을 자동으로 붙이기"이며, **착수 전에
끝내기로 한 선행조건 넷 중 둘이 비어 있다.**

| | 선행조건 | 상태 |
| --- | --- | --- |
| 1 | 홀드아웃 열기 | 유출 교체는 끝났다. 여는 것은 아직 |
| 2 | 착수 기준 확정 | 모양은 정해졌고 값이 비어 있다 (표본 100건에 1인이 3단 라벨을 붙여 그 자리에서 선을 긋는다. 기준 항목은 AM4와 AH1) |
| 3 | **유사도 선별기 문턱값 0.60 재설정** | 근거 자료가 생겼다 — 697건의 `restatement_ratio` 분위수 |
| 4 | **`direct_impact`의 사실 정확성 채점 항목 신설** | 아무것도 없다. **방향을 거꾸로 쓴 문장이 AM1~AM8·AH1을 전부 통과해서 나왔다** |

**같이 볼 것** — AM8 채점기가 주체를 문장에 통째로 들어 있는지로만 봐서 오탐을 낸다.
697건에서 실패 109건 중 56건이 오탐이었고, 대안 구현이 `export.py`의 `subject_survives()`에
이미 있다. A-2를 돌리기 전에 정해야 수치가 처음부터 맞는다.

**정해야 하는 것 둘** — 605건의 계열 쏠림(처리방침 60%)을 학습·평가 분할에 어떻게
반영할지, negative 45%를 목표치 10%로 줄일지. 둘 다 코드가 아니라 판단이다.

## 역할 B 세션 — 생성

원천 조항 하나와 `(대상, 방향)` 지시를 받아 그 변경이 일어난 개정문을 쓴다.
설계는 `docs/학습데이터_생성_프로세스.md` 3-3절, 경위는 `training_data/mutate/CHANGELOG.md`.

**지금 상태 — 2026-08-12에 새 교사 모델로 기준선을 다시 잡았다**

| | 옛 모델 | 새 모델 |
| --- | ---: | ---: |
| BM5 왕복 검증 | 53.3% | **78.3%** |
| BM7 문장 검사 | 88.3% | 81.7% |
| 폐기 | 1 | **0** |
| 주체 표현 가짓수 | 6가지 | **11가지** (최빈 표현 62% → 20%) |

프롬프트는 v1.2, 온도 0.9. 사람 검수 60건에서 BH1 51/60 = 85%였다. 도구는
`generate.py` · `run.py` · `rejudge.py`(재판정, 생성 호출 0) · `review.py`(사람 검수)
· `sample.py` · `blind_export.py`가 있다.

**잡음 바닥은 아직 안 재봤다.** 자주 인용되는 "뒤집힘 7건(12.3%)"은 잡음 바닥이 아니다
— 그 재판정(`20260812T022411…`)의 `source_run`은 **옛 모델이 생성한 v1.1**이고 판정만
새 모델로 바꾼 것이라, **판정 모델 교체 효과와 판정 자체의 흔들림이 섞여 있다.** 7건은
잡음의 **상한**이고 진짜 바닥은 그보다 낮다. 이미 새 모델로 판정된 실행을 같은 모델로
한 번 더 돌려야 나오며, 그게 아래 4번이다. **바닥이 나오기 전에는 "BM5가 몇 건 움직여야
개선인가"를 확정할 수 없다.**

**다음 할 일 넷**

| | 무엇 | 왜 |
| --- | --- | --- |
| 1 | **합성에 복수 변경을 넣을지 정한다** | 실제 pair는 한 블록에 라벨 2개 이상이 18%인데 합성은 2%다. 프롬프트 규칙 6("지시한 변경 하나만")의 결과이고, **이대로 6,000건을 뽑으면 복수 변경은 안 배운다** |
| 2 | **지시 배분을 고친다** | `수행 주체`가 59.6%로 상한 25%를 2.4배 넘는다. 성립 판정은 버틸 만하고 **문제는 고르는 순서다** — `applicable()`이 `수행 주체`를 맨 앞에 두고 `generate.py`가 앞 둘만 집는다 |
| 3 | **v1.2 결과 60건을 다시 채점한다** | BM5a가 5/12 → 10/12로 오른 것은 역할 A 눈에 그렇다는 뜻이다. **기계 채점자를 먼저, 사람을 나중에** — 순서를 지켜야 새 BH1 정의의 일치도가 같이 나온다 |
| 4 | **판정 잡음 바닥을 잰다 (60호출)** | `python3 training_data/mutate/rejudge.py <실행> --plan plans/sample60.json` |

**안 건드리는 것** — `docs/` 전부와 `training_data/interpret/`. 문서에 반영할 것이
생기면 역할 A 세션에 넘긴다.

**`text_check.py`의 정규식에 알려진 오탐이 있다.** C4의 `SUBJ`가 용언 어간을 주어로
잡고(`수행하려`는), C1의 `JOSA`가 관형형 어미 `-는`을 조사로 오인한다. 형태소
분석기(Kiwi)로 갈면 한 번에 잡히지만, **지금 수치가 옛 규칙 기준이라 갈면 같은 60건을
옛·새 둘 다로 돌려 차이를 봐야 한다.**
