# 세션 브리프

**세션을 시작할 때 이것만 읽는다.** 자기 역할 절과 아래 「공통」만 보면 되고, 다른
역할 절은 안 읽어도 된다. 더 필요할 때만 각 절이 가리키는 문서로 내려간다.

이 문서는 **오늘 어디서 이어 하는지**를 적는다. 설계는 `학습데이터_생성_프로세스.md`,
경위는 각 역할의 `CHANGELOG.md`, 할 일 목록은 `TODO.md`에 있다.

끝내기로 한 선행조건 넷 중 둘이 비어 있다.**

| --- | --- | --- |

| 2 | 착수 기준 확정 | 모양은 정해졌고 값이 비어 있다 (표본 100건에 1인이 3단 라벨을 붙여 그 자리에서 선을 긋는다. 기준 항목은 AM4와 AH1) |
| 3 | **유사도 선별기 문턱값 0.60 재설정** | 근거 자료가 생겼다 — 697건의 `restatement_ratio` 분위수 |
| 4 | **`direct_impact`의 사실 정확성 채점 항목 신설** | 아무것도 없다. **방향을 거꾸로 쓴 문장이 AM1~AM8·AH1을 전부 통과해서 나왔다** |

**같이 볼 것** — AM8 채점기가 주체를 문장에 통째로 들어 있는지로만 봐서 오탐을 낸다.

이미 있다. A-2를 돌리기 전에 정해야 수치가 처음부터 맞는다.

**정해야 하는 것 둘** — 605건의 계열 쏠림(처리방침 60%)을 학습·평가 분할에 어떻게
반영할지, negative 45%를 목표치 10%로 줄일지. 둘 다 코드가 아니라 판단이다.

### 2026-08-13에 고친 것 넷 — 전부 `generate.py`

**탐침을 먼저 돌려서 찾았다.** 100건(1차)과 60건(재탐침)에 25분을 썼고, 그냥 본 생성을
갔으면 **277건이 지시와 어긋난 채로** 나왔을 것이다. 폐기가 아니라 라벨이 갈아끼워지면서
채우려던 칸이 조용히 비었을 것이라 **5시간을 다 쓰고 나서야 알았다.**

| | 무엇 | 효과 |
| --- | --- | --- |
| 1 | 지시 배분 — 성립하는 지시를 전부 후보에 담고, 조항당 상한은 뽑을 때 걸고, **공급이 적은 지시부터** 고른다 | `수행 주체` 59.6% → 21.9% |
| 2 | `NUMBER`에 `개(?!월)` — 경계가 없어 `3개월`이 `3개`로 걸렸다 | `수치·기준` 지시가 기한 조항에 걸리던 8건이 0건 |
| 3 | `(수치·기준, 다른 값)` → **`늘었다` + `줄었다`** | BM5 **5% → 95%** |
| 4 | `(기한·시점, 다른 값)` → **`늘었다` + `줄었다`** | BM5 **17% → 90%** |

3·4번은 `(절차·요건, 늘었다)` → `새로 생겼다`와 같은 자리다. **수가 바뀌면 늘거나 줄지
"다른 값"이 되지 않는다.** 역할 A가 대상은 잘 회수하는데(89%) 방향 이름이 달라 BM5만
깎이고 있었다. **정의로 정한 것이 아니라 A가 실제로 어떻게 읽는지로 정했다.**

재탐침은 같은 조항에 `늘었다`·`줄었다`를 둘 다 걸어 **방향 지시만 다른 짝 비교**로 했다.
30쌍 중 `지시대로 갈렸다` 20쌍, `조항이 방향을 정한다` 3쌍. **합격 기준을 결과 보기 전에
확정**해 두고 통과시켰다(`조항이 방향을 정한다` 10쌍 미만 + 건별 BM5 58% 이상. 58%는
이미 받아들인 지시 중 제일 낮은 값이라 임의값이 아니다).

### `model_train`이 우리 산출을 어떻게 쓰는지 — 2026-08-13에 맞춘 것

옆 저장소 세션과 직접 맞춰본 사실이다. **합성분에 홀드아웃 계열이 섞여 나간다.**

| | |
| --- | --- |
| 본 생성 1,459건 중 `mof_rd_regulation_pair` 씨앗 | **240건 (16.4%)** |
| `model_train`의 홀드아웃 | 바로 그 `mof_rd_regulation_pair` 37건 |

**합성 pair는 원천 조항을 그대로 가져다 개정문만 새로 쓴다.** 개정문이 새것이어도 모델은
그 조항을 본 셈이라 **평가 점수가 부풀려진다.** 게다가 `series`에 `synth:` 접두가 붙어
`model_train`이 정확일치로 거르던 홀드아웃 필터에 **안 걸리고 있었다.**

- **아직 안 고쳤다 (2026-08-14 확인).** 이 자리에 "옆 세션이
  `series.removeprefix('synth:')`로 고쳤다"고 적혀 있었으나 **사실이 아니라 되돌린다.**
  `model_train`의 `sft/records.py:77`은 지금도 `record["series"] == HOLDOUT_SERIES`
  정확일치다 — 옆 세션이 고치겠다고 말했을 뿐 파일을 안 건드렸다. **학습 데이터를
  가르기 전에 반드시 넣는다.** 안 넣으면 240건이 학습셋으로 들어가고 채점이 부풀려진다
- **근본 해법은 홀드아웃 문서를 씨앗에서 빼는 것**이다. `documents.py`에서 그 두 문서를
  빼면 애초에 안 생기고 생성 시간도 50분 아낀다. **아직 안 정했다** — 2,000건 목표와
  계열 분포에 걸리므로 역할 A·사용자 판단이다
- 우리 `scores`에는 `BM*`만 있고 `AM*`가 없다. 옆 저장소가 `scores.AM1`으로 걸러서
  전량이 조용히 버려질 뻔했다. 최종 파일에 `scores`를 안 담기로 정리됐다. **다만
  `model_train` 쪽 방어 코드**(`scores`는 있는데 `AM1`이 없는 경우를 통과시키는 것)**도
  아직 안 들어갔다**
