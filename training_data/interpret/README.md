# interpret — 역할 A (해석 붙이기)

두 버전 사이의 차이를 받아 **무엇이 왜 바뀌었고 누구에게 영향이 있는지**를 쓴다.
대화에서는 홈즈라고 부른다.

## 입력

`source_data/classify_diff.py`가 낸 `<앞>__<뒤>.classify.json`. 그 안에서 모델에 가는 것은
규칙을 통과한 블록쌍(`real_change.items[].blocks[]`)과 짝이 없는 추가·삭제 블록이다.
기계 negative(`no_real_change.items[]`)는 2단계에서 이미 걸러졌으므로 가지 않는다.

블록쌍에 상위 제목·인접 조항·참조 정의를 얼마나 붙일지는 **아직 정하지 않았다.** 문서
전체를 넣지 않는다는 방침만 정해져 있다(`docs/선행연구_분석.md` 3절). 문서 전체를 한
프롬프트에 넣은 실험이 `probes/prompt_test/`이고, 검증된 변경을 온전히 잡은 실행이 10번 중
0번이었다.

## 출력

3단 라벨(negative/positive → 대상 7종 → 방향 5종)과 `근거 → 영향 대상 → 직접 영향 →
제한된 해석` 필드. 라벨 정의는 `docs/학습데이터_생성_프로세스.md` 2절에 있다.

## 사람이 하는 부분

**라벨 판정은 사람이 한다.** `probes/interpret_probe/`에서 Solar의 라벨 일치가 6건 중 3건이었고
틀린 답에도 `high` 신뢰도가 붙었다. 반반 확률의 라벨을 few-shot 예시에 넣을 수 없다.
Solar에게 맡기는 것은 `direct_impact` 문장 작성이다.

## 구현

아직 없다. `docs/PLAN.md` 2번(입출력 확정)이 끝나야 시작한다.
