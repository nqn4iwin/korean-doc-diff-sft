# mutate — 역할 B (쌍 만들기)

원문 조항 하나와 적용할 변경 지시를 받아 **그 변경이 실제로 일어난 개정문**을 쓴다.
결과는 원문과 짝지어 새 pair가 된다. 대화에서는 모리아티라고 부른다.

역할 A(해석)의 환경은 `../interpret/`에 있다. 두 역할은 **같은 라벨 체계를 쓴다** —
그것이 이 설계의 전제다.

## 입력

원천 문서의 조항 하나와 **`(대상, 방향)` 한 쌍**, 그리고 그 쌍의 판정 기준.
`probes/mutate_probe/`의 결론이 "이름만 주면 안 된다"였다.

## 출력

수정된 조항. **모델이 신고한 `changed_span`은 받지 않는다.** 자기신고가 재현된 비율이
61%였다. 바뀐 구간은 `source_data/classify_diff.py`로 다시 계산한다.

## 지시 어휘는 `(대상, 방향)`이다 — 옛 연산자 이름이 아니다

`probes/mutate_probe/`는 `threshold_increased`·`obligation_weakened` 같은 **8종 연산자**로
돌렸다. 그 어휘는 제안요청서 실험에서 나온 13종 체계의 일부이고, **버려졌다**
(`docs/PLAN.md` 1번). 지금 체계는 실제 pair 20쌍에서 다시 귀납한 대상 7종 × 방향 5종이며
정의는 `docs/학습데이터_생성_프로세스.md` 2절에 있다.

대응은 대충 이렇지만 1:1이 아니다. `scope_expanded`는 `(적용 범위, 늘었다)`에 가깝고
`deadline_changed`는 `(기한·시점, 다른 값)`에 가깝다. 반면 `obligation_strengthened`는
새 체계에 대응하는 칸이 없다 — 새 체계의 축은 "무엇이 바뀌었나"와 "어느 쪽으로"이지
"의무의 세기"가 아니다.

**옛 어휘가 아직 남아 있는 곳이 둘이다.** 쓰기 전에 갈아야 한다.

- `probes/mutate_probe/run.py` — 실험 기록이므로 그대로 두고 재사용하지 않는다
- `source_data/block_components.py` — 조항에 어떤 연산자를 걸 수 있는지 판정한다.
  새 체계로 키를 다시 잡아야 쓸 수 있다. **다만 급하지 않다** — 아래를 본다

## 조항마다 걸 수 있는 지시가 다르다

`mutate_probe`에서 36건을 돌려 21건만 지시한 연산자가 복원됐는데, 실패의 대부분은 모델
오류가 아니라 **조항에 그 변경을 넣을 자리가 없는 조합**이었다. 수치가 없는 대리인 조항에
`threshold_increased`를 지시한 것이 그 예다. 모델은 시킬 수 없는 일을 못 하므로 가장
가까운 다른 개정을 했고, 판정은 그 다른 개정을 정확히 짚었다 — **양쪽 다 옳게 동작했고
지시가 틀렸다.**

자리 판정 없이 일괄 적용하면 산출의 25~30%가 지시와 어긋난다. 그 표를 만드는 것이
`docs/PLAN.md` 4번이고, `source_data/block_components.py`가 그 절반이다.

**그런데 지금 쓰는 표층 판정이 버틸 만하다는 것이 2026-08-12에 확인됐다.** `generate.py`의
정규식이 조항에 무엇이 들어 있는지 보고 지시를 고르는데, 새 교사 모델 60건에서
`(수행 주체, 늘었다)` 19/20 · `(수행 주체, 다른 값)` 18/20 · `(기한·시점, 다른 값)` 2/2 ·
`(제출물·기재사항, 늘었다)` 2/2가 나왔다. **자리가 없는 지시를 걸고 있었다면 이렇게 안
나온다.**

**막고 있는 것은 성립 판정이 아니라 고르는 순서다.** `applicable()`이 `수행 주체`를 목록
맨 앞에 두고 `generate.py`가 `allowed[:2]`로 앞 둘만 집으므로, 주체 표기가 있는 조항이면
두 자리를 늘 주체가 먹는다. 전체 코퍼스에 걸면 `수행 주체`가 합쳐서 **59.6%**로
`docs/기획서_최종.md` 2.3절의 25% 상한을 2.4배 넘고 `수치·기준`은 1.5%밖에 안 나온다.
성립하는 지시가 3개 이상인 조항이 1,684개인데 전부 앞 두 개만 쓰인다.

## 역할 A에게 알려주지 않는 것

B가 받은 지시를 A에게 알려주지 않는다. 알려주면 A의 `direct_impact`가 라벨 이름을 풀어쓴
문장이 되어 전체가 같은 문체가 된다(`docs/기획서_최종.md` 2.2.2절). 역할 A의 v2.1이
이것을 실측으로 확인했다 — 예시 문구 하나가 영향 칸 45개 중 39개를 같은 틀로 만들었다.

## 채점

`rubric.md`에 있다. 핵심은 **왕복 검증**이다 — B가 쓴 개정문을 원문과 짝지어 A에게 blind로
넣고, A가 같은 `(대상, 방향)`을 짚으면 통과다. 정답 개정문이 하나가 아니므로 문자열
대조로는 채점할 수 없기 때문이다.

**다만 A의 라벨 회수율이 이 게이트의 상한이다.** 사람 라벨 27개로 잰 값이 44%였다.

**교사 모델을 갈고 다시 재면 BM5가 78.3%다**(2026-08-12, 같은 조항·같은 지시 60건을
짝지어 비교. 옛 모델 53.3%). 남은 실패는 `절차·요건` 하나에 몰려 있다 — 12건 중 2건만
회수된다. 자세한 것은 `CHANGELOG.md`.

**BM5는 품질 게이트가 아니라 라벨 정합성 검사다.** 실패해도 데이터는 남고 A가 준 라벨로
갈아 끼운다(`docs/기획서_최종.md` 2.3절). 그래서 BM5가 44%든 90%든 최종 데이터 양은 거의
같다. 급한 것은 라벨 정확도가 아니라 **문장과 다양성**이다.

## 구현

`run.py`가 생성과 왕복 검증을 한 번에 돈다. 조건 여러 개를 한 번의 실행으로 비교할 수
있다.

```
python training_data/mutate/run.py --prompt v0.1 v0.2 v0.3
```

생성은 temperature 0.9(같은 조합 3회가 서로 달라야 표본이 는다), 판정은 0.2(흔들리면 안
된다)로 돈다. `solar_request.json`이 온도를 고정하고 있어 페이로드를 만든 뒤 덮어쓴다.

`generate.py`는 그렇게 깎은 프롬프트를 문서 하나에 통째로 적용한다. 조항을 고르고 지시를
정하는 일까지 기계가 한다. `--concurrency`로 요청을 여러 개 동시에 띄운다 — 한 건씩
보내면 서버에 요청이 항상 하나만 떠 있어 GPU가 논다.

```
python3 training_data/mutate/generate.py DOC --prompt v1.1 --limit 180 --concurrency 16
```

**`--plan`으로 계획을 밖에서 받으면 같은 조항 × 같은 지시를 다시 돌린다.** 모델이나
프롬프트를 바꾼 뒤 좋아졌는지 보려면 이것이 필요하다 — 계획을 새로 세우면 조항이 달라져
두 실행을 맞댈 수 없고 평균 두 개만 비교하게 된다. 짝을 지으면 뒤집힌 건수를 직접 셀 수
있어 훨씬 예민하다.

```
python3 training_data/mutate/generate.py DOC --prompt v1.1 --plan plans/sample60.json
```

계획 파일은 `sample.py`가 옛 실행에서 지시 구성을 보존해 뽑는다. **다만 재현해야 할 것은
뽑는 절차가 아니라 뽑힌 결과이므로 계획 파일 자체를 `plans/`에 남기고 그것을 계속 쓴다.**
`plans/sample60.json`이 지금의 기준선이다.

`rejudge.py`는 **이미 뽑아 놓은 개정문을 다시 판정만** 한다. 생성 호출이 없다. 모델을
바꾸면 BM5가 "생성이 좋아져서"인지 "판정이 달라져서"인지 섞이는데, 이 경로가 있으면
칸을 갈라 볼 수 있다.

```
python3 training_data/mutate/rejudge.py runs/<실행 디렉터리> --plan plans/sample60.json
```

`documents.py`는 합성에 쓸 원천 문서를 중복 없이 고른다. `.hwpx`와 `.txt`가 같은 문서라
둘 다 돌리면 같은 조항이 두 번 들어간다. **어느 형식을 쓸지는 확장자가 아니라 조항이
실제로 나오는지로 정한다** — 확장자 순서로 골랐더니 `extract.py`가 못 읽는 옛 `.hwp`를
집어 조항 730개짜리 `.txt`가 버려졌다.

```
python3 training_data/mutate/documents.py              # 목록과 조항 수
python3 training_data/mutate/documents.py --paths      # 셸 반복문에 먹인다
```

`review.py`가 그 산출물을 **사람이 채점할 HTML 한 장**으로 묶는다. 기계 게이트는
`generate.py`가 매기지만 **BH1(개정문다움)은 사람이 읽어야 하고**, `pairs.json`을 그대로
읽으면 한 건이 수십 줄이라 100건을 훑을 수 없다. 바뀐 곳에 색을 입히고, 역할 A의 해석은
접어 두고(BH1은 개정문만 보고 매긴다), 점수를 `localStorage`에 남겨 나눠서 볼 수 있게 한다.

```
python3 training_data/mutate/review.py runs/<실행 디렉터리>
python3 training_data/mutate/review.py runs/<실행 디렉터리> --limit 160 --bucket all
```

기본값은 `학습 후보`와 `라벨 교체 후보` 100건이다. 결과는 페이지 맨 아래에 탭 구분 표로
쌓인다.

**「지시 가리기」가 기본으로 켜져 있다.** 지시와 버킷과 BM5를 가린다 — 셋 다 지시를
역산할 수 있기 때문이다(`라벨 교체 후보`는 "BM5 실패"라는 뜻이다). 답을 보고 답을 맞히지
않게 하려는 것이고, 왕복 검증이 A에게 B의 지시를 안 알려주는 것과 같은 이유다.

**「무엇을 했나」 칸은 잘했는지가 아니라 어떤 수를 뒀는지를 적는다.** 다음 프롬프트 판본이
무엇을 가르쳐야 하는지는 이 분포에서 나온다 — 2026-08-12 실측에서 `(절차·요건, 늘었다)`
12건이 전부 "명사 목록에 항목 하나 끼워넣기" 한 수였고, 그 수가 목록의 성격에 따라
`절차·요건`으로도 `적용 범위`로도 읽혀 라벨이 샜다.

**「파일로 저장」을 중간중간 누른다.** 점수는 `localStorage`에도 남지만 브라우저 저장소를
비우면 사라진다. 실제로 검수하던 것을 한 번 잃었다.
