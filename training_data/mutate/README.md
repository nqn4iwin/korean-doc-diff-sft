# mutate — 역할 B (쌍 만들기)

원문 조항 하나와 적용할 변경 지시를 받아 **그 변경이 실제로 일어난 개정문**을 쓴다.
결과는 원문과 짝지어 새 pair가 된다. 대화에서는 모리아티라고 부른다.

역할 A(해석)의 환경은 `../interpret/`에 있다. 두 역할은 **같은 라벨 체계를 쓴다** —
그것이 이 설계의 전제다.

## 입력

원천 문서의 조항 하나와 **`(대상, 방향)` 한 쌍**, 그리고 그 쌍의 판정 기준.
`probes/mutate_probe/`의 결론이 "이름만 주면 안 된다"였다.

## 출력

수정된 조항. **모델이 신고한 `changed_span`은 받지 않는다.** 자기신고가 재현된 비율이
61%였다. 바뀐 구간은 `source_data/classify_diff.py`로 다시 계산한다.

## 지시 어휘는 `(대상, 방향)`이다 — 옛 연산자 이름이 아니다

`probes/mutate_probe/`는 `threshold_increased`·`obligation_weakened` 같은 **8종 연산자**로
돌렸다. 그 어휘는 제안요청서 실험에서 나온 13종 체계의 일부이고, **버려졌다**
(`docs/PLAN.md` 1번). 지금 체계는 실제 pair 20쌍에서 다시 귀납한 대상 7종 × 방향 5종이며
정의는 `docs/학습데이터_생성_프로세스.md` 2절에 있다.

대응은 대충 이렇지만 1:1이 아니다. `scope_expanded`는 `(적용 범위, 늘었다)`에 가깝고
`deadline_changed`는 `(기한·시점, 다른 값)`에 가깝다. 반면 `obligation_strengthened`는
새 체계에 대응하는 칸이 없다 — 새 체계의 축은 "무엇이 바뀌었나"와 "어느 쪽으로"이지
"의무의 세기"가 아니다.

**옛 어휘가 아직 남아 있는 곳이 둘이다.** 쓰기 전에 갈아야 한다.

- `probes/mutate_probe/run.py` — 실험 기록이므로 그대로 두고 재사용하지 않는다
- `source_data/block_components.py` — 조항에 어떤 연산자를 걸 수 있는지 판정한다.
  **새 체계로 다시 키를 잡아야 실제로 쓸 수 있다**

## 조항마다 걸 수 있는 지시가 다르다

`mutate_probe`에서 36건을 돌려 21건만 지시한 연산자가 복원됐는데, 실패의 대부분은 모델
오류가 아니라 **조항에 그 변경을 넣을 자리가 없는 조합**이었다. 수치가 없는 대리인 조항에
`threshold_increased`를 지시한 것이 그 예다. 모델은 시킬 수 없는 일을 못 하므로 가장
가까운 다른 개정을 했고, 판정은 그 다른 개정을 정확히 짚었다 — **양쪽 다 옳게 동작했고
지시가 틀렸다.**

자리 판정 없이 일괄 적용하면 산출의 25~30%가 지시와 어긋난다. 그 표를 만드는 것이
`docs/PLAN.md` 4번이고, `source_data/block_components.py`가 그 절반이다.

## 역할 A에게 알려주지 않는 것

B가 받은 지시를 A에게 알려주지 않는다. 알려주면 A의 `direct_impact`가 라벨 이름을 풀어쓴
문장이 되어 전체가 같은 문체가 된다(`docs/기획서_최종.md` 2.2.2절). 역할 A의 v2.1이
이것을 실측으로 확인했다 — 예시 문구 하나가 영향 칸 45개 중 39개를 같은 틀로 만들었다.

## 채점

`rubric.md`에 있다. 핵심은 **왕복 검증**이다 — B가 쓴 개정문을 원문과 짝지어 A에게 blind로
넣고, A가 같은 `(대상, 방향)`을 짚으면 통과다. 정답 개정문이 하나가 아니므로 문자열
대조로는 채점할 수 없기 때문이다.

**다만 A의 라벨 회수율이 이 게이트의 상한이다.** 그 값이 지금 44%이므로 게이트를 그대로
쓸 수 없다. 자세한 것은 `rubric.md`.

## 구현

`run.py`가 생성과 왕복 검증을 한 번에 돈다. 조건 여러 개를 한 번의 실행으로 비교할 수
있다.

```
python training_data/mutate/run.py --prompt v0.1 v0.2 v0.3
```

생성은 temperature 0.9(같은 조합 3회가 서로 달라야 표본이 는다), 판정은 0.2(흔들리면 안
된다)로 돈다. `solar_request.json`이 온도를 고정하고 있어 페이로드를 만든 뒤 덮어쓴다.

`generate.py`는 그렇게 깎은 프롬프트를 문서 하나에 통째로 적용한다. 조항을 고르고 지시를
정하는 일까지 기계가 한다. `--concurrency`로 요청을 여러 개 동시에 띄운다 — 한 건씩
보내면 서버에 요청이 항상 하나만 떠 있어 GPU가 논다.

```
python training_data/mutate/generate.py DOC --prompt v1.1 --limit 180 --concurrency 16
```

`review.py`가 그 산출물을 **사람이 채점할 HTML 한 장**으로 묶는다. 기계 게이트는
`generate.py`가 매기지만 **BH1(개정문다움)은 사람이 읽어야 하고**, `pairs.json`을 그대로
읽으면 한 건이 수십 줄이라 100건을 훑을 수 없다. 바뀐 곳에 색을 입히고, 역할 A의 해석은
접어 두고(BH1은 개정문만 보고 매긴다), 점수를 `localStorage`에 남겨 나눠서 볼 수 있게 한다.

```
python training_data/mutate/review.py runs/<실행 디렉터리>
python training_data/mutate/review.py runs/<실행 디렉터리> --limit 160 --bucket all
```

기본값은 `학습 후보`와 `사람 확인 필요` 100건이다. 결과는 페이지 맨 아래에 탭 구분 표로
쌓인다.
