# 채점 기준 (역할 B)

프롬프트를 고친 뒤 좋아졌는지 판단하는 잣대다. **출력을 보기 전에 정한다.**

역할 A(`../interpret/rubric.md`)와 구조는 같게 두되, **정답이 하나가 아니라는 점이
다르다.** A는 사람이 붙인 정답 라벨과 대조할 수 있지만, B의 산출은 "이 조항에 이 변경을
넣은 개정문"이라 옳은 답이 여럿이다. 문자열 대조로는 채점할 수 없다.

## 그래서 왕복 검증을 쓴다

B가 쓴 개정문을 원문과 짝지어 **역할 A에게 blind로 넣는다.** A가 지시받은 것과 같은
`(대상, 방향)`을 짚으면 통과다. A는 B가 무슨 지시를 받았는지 모른다.

```
원문 조항 + 지시 (대상, 방향)
        ↓  역할 B
     개정문
        ↓  원문과 짝지어
   역할 A (blind)
        ↓
   labels 에 지시받은 쌍이 들어 있는가
```

**완전일치가 아니라 포함으로 본다.** A가 다른 라벨을 더 붙이는 것은 벌하지 않는다. B가
한 군데를 고쳐도 그 고침이 두 가지 성격을 함께 띠는 일이 흔하기 때문이다 —
`mutate_probe`의 `손해배상 등 책임에 관한 사항` → `손해배상에 관한 사항`이 범위 축소이자
의무 완화였던 것이 그 사례다. A가 사람 라벨에 없는 것을 덧붙이는 것은 v2.2에서 호출당
평균 0.7개였다.

## 이 게이트에는 상한이 있다 — 지금은 44%다

**A가 회수하지 못하는 라벨은 B가 아무리 잘 써도 통과할 수 없다.** 그래서 게이트를 쓰기
전에 A의 라벨 회수율을 먼저 재야 한다. 역할 A v2.2에서 실측한 값이다(positive 5항목,
사람 라벨 27개).

| `(대상, 방향)` | A의 회수 |
| --- | ---: |
| (수행 주체, 늘었다) | 3/3 100% |
| (수행 주체, 다른 값) | 3/3 100% |
| (절차·요건, 새로 생겼다) | 3/3 100% |
| (절차·요건, 늘었다) | 3/6 50% |
| (명칭, 다른 값) | 0/6 **0%** |
| (적용 범위, 줄었다) | 0/3 **0%** |
| (적용 범위, 다른 값) | 0/3 **0%** |
| **전체** | **12/27 44%** |

**고르게 낮은 것이 아니라 갈린다.** 그리고 0%인 셋은 원인이 이미 밝혀져 있다.

- **(적용 범위, 다른 값)** — 긍정↔부정 전환을 `다른 값`으로 본다는 규칙을 문서에만 쓰고
  프롬프트에 안 넣었다. `docs/TODO.md`에 있는 한 줄짜리 수정이다.
- **(명칭, 다른 값)** — A가 `제출물·기재사항`으로 판정한다. 두 대상의 경계가 프롬프트에서
  안 갈린다(`../interpret/CHANGELOG.md` v1 항목).
- **(적용 범위, 줄었다)** — A가 방향을 반대로 냈다.

**따라서 순서가 정해진다.** B의 지시 어휘를 A가 회수하는 것부터 열고, 나머지는 A를 고친
뒤에 연다. 세 가지 다 A의 문제이지 B의 문제가 아니므로, B를 깎아서는 안 오른다.

## 채점 항목

`run.py`가 자동으로 매기는 것(`BM`)과 사람이 읽는 것(`BH`)으로 가른다. 확정 전 초안이다.

**이름은 두 글자로 읽는다 — 앞이 역할, 뒤가 채점자다.** `B`는 역할 B(생성), `M`은
기계, `H`는 사람이다. 역할 A(해석)는 `interpret/rubric.md`에 `AM`·`AH`로 있고, 거기에
옛 이름 대응표가 있다.

| # | 항목 | 1점인 경우 |
| --- | --- | --- |
| BM1 | JSON 파싱 | 출력이 JSON 하나로 파싱된다 |
| BM2 | 실제로 달라졌나 | 원문과 개정문이 다르고, `classify_diff.py`의 정규화 규칙에 걸리지 않는다 |
| BM3 | 용어 비노출 | `절차·요건` 같은 분류 어휘가 개정문 본문에 새어 들어가지 않았다 |
| BM4 | 국소 수정 | 조항 전체를 새로 쓰지 않았다. 바뀐 구간이 조항 길이의 일정 비율 이하다 |
| BM5 | **왕복 검증** | A가 지시받은 `(대상, 방향)`을 짚었다 |
| BM6 | 변형 다양성 | 같은 조합 3회가 서로 다른 개정문이다 |
| BM7 | 문장 검사 | 비문·지어냄·참조 깨짐으로 의심되는 곳이 없다 (`text_check.py`) |
| BH1 | 개정문다움 | 실제 공문서 개정문으로 읽히는가. 문체·어투가 원문 계열과 맞는가 |

**BM7은 하드 게이트가 아니라 표시다.** 걸린 것은 버리지 않고 `사람 확인 필요` 버킷으로
보낸다. 사람이 판정한 표본이 10건뿐이라 문턱을 세울 근거가 없기 때문이다.

BM7이 필요한 이유는 **BM1~BM5 어디에도 문장이 말이 되는지 보는 자리가 없어서**다. 첫
문서 실행에서 다섯 게이트를 모두 통과한 10건 중 셋이 비문이거나 지어낸 것이었고, 셜록은
셋 다 지시한 라벨로 정확히 판정했다. 규칙 넷은 그 실패에서 거꾸로 뽑았다.

| | 무엇을 보나 | 잡은 것 |
| --- | --- | --- |
| C1 | 주체를 접속해 놓고 주격·주제 조사로 닫지 않았다 | `사업담당관 및 자체 연구개발과제의 …` |
| C2 | 새로 세운 주체가 문서 어디에도 없다 | `과제담당관 및 관련 업무의 장은` |
| C3 | 새 수치가 문서 어디에도 없다 | (`수치·기준`·`기한·시점` 지시에는 걸지 않는다) |
| C4 | 다른 조항을 받는 조항에서 주체를 통째로 갈았다 | `제1항에 따라 5급 이상 공무원은` |

**이 검사를 Solar에게 시키지 않는다.** 모리아티가 지어낸 `5급 이상 공무원`을 셜록이
사실로 읽었다 -- 같은 모델은 같은 오류를 낸다.

C3에 예외를 둔 이유가 중요하다. `수치·기준`과 `기한·시점`은 **새 값을 넣으라는 지시**라
문서에 없는 값이 나오는 것이 정상이다. 예외를 안 두면 정당한 개정을 지어냄으로 잡는다.
실제로 첫 판에서 `2025년`을 그렇게 잡았다.

**측정** -- 사람이 읽은 10건에서 문제 3건을 전부 잡았고 오탐 0이었다. 사람이 아직 안 읽은
`라벨 교체 후보` 9건에서도 3건을 짚었다(`6급`, `수요기관의 장`, `10호` -- 모두 문서에
없다). 다만 표본이 10건이므로 이 수치를 믿고 하드 게이트로 올리면 안 된다.

`mutate_probe` 36건에서 BM1은 36/36, BM3은 36/36, BM6은 35/36이었다. **이미 되는 것들이라
게이트로서 의미가 적고, 무너지는지 지켜보는 용도다.** 실제로 가르는 것은 BM5다.

BM4의 "일정 비율"은 아직 정하지 않았다. `mutate_probe`는 국소 수정을 지시로만 넣고 재지
않았다.

## 지키는 규칙

역할 A와 같다. 한 라운드에 한 군데만 고치고, 같은 항목을 3회씩 돌리고, 홀드아웃은
평소에 열지 않고, 되돌린 시도도 `CHANGELOG.md`에 남기고, 세 번 고치면 멈춘다.

**A와 다른 것이 하나 있다.** B의 채점은 A를 거치므로 **A의 프롬프트 판본을 함께
기록해야 한다.** A가 바뀌면 같은 B 출력의 점수가 달라진다. 기록 없이 비교하면 B를 고친
효과와 A가 바뀐 효과가 섞인다.
