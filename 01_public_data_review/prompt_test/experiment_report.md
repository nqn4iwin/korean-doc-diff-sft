# 01 공공데이터 이용규약 질의응답 Solar 실험 결과

## 결론

Solar Open 2는 국립중앙과학관 데이터의 상업적 활용과 서비스 사용 데이터의 기업 제공
가능성을 묻는 동일한 질문에 대해 10회 모두 `조건부 이용 가능`이라는 같은 판정을 내렸다.
상업적 이용 신청·계약, 제3자 권리, 재배포 제한, 출처표시, 기관 확인 필요성도 반복적으로
포착했으므로, 고정된 RAG 근거를 바탕으로 핵심 쟁점을 해석하는 기본 능력은 확인됐다.

그러나 10회 중 3회에서 입력에 존재하지 않는 근거 ID인 `E06` 또는 `E07`을 인용했다.
결론은 안정적이었지만 근거 ID 정확도는 7/10이므로, 현재 상태를 그대로 근거 기반
질의응답 서비스에 적용하기에는 검증 장치가 필요하다.

이번 단일 사례만으로 SFT의 필요성이 입증됐다고 보기는 어렵다. 현재 잠정 판정은 다음과
같다.

> 프롬프트-only 조건에서도 핵심 판정과 쟁점 추출은 안정적이었다. 발견된 주요 오류는
> 허용된 근거 ID 밖의 값을 생성한 것이며, 이는 우선 구조화 출력, ID 검증, 오류 시 재요청
> 같은 저비용 통제로 해결 가능한지 확인해야 한다. 다양한 사례에서도 같은 오류가 반복되고
> 이러한 통제로 해결되지 않을 때 SFT의 추가 가치를 판단하는 것이 타당하다.

## 실험 구성

- 모델: `solar-open2-250b`
- 실행 횟수: 10회
- 성공한 API 호출: 10회
- 실패한 API 호출: 0회
- reasoning_effort: `low`
- temperature: `0.7`
- top_p: `1.0`
- max_tokens: `4096`
- 재시도: 없음
- 입력 질문: `국립중앙과학관 데이터를 이용해 유료 AI 생물도감 서비스를 만들고, 그 사용 데이터를 기업 고객에게 제공해도 돼?`
- 입력 근거: 공공데이터포털 메타데이터 1건과 국립중앙과학관 정보 제공·관리 규정에서 구성한 고정 청크 4건
- 근거 ID: `E01`~`E05`
- 실행 결과: `runs/01_20260731T090906.241538Z/`

추론을 활성화했던 앞선 실행에서는 내부 추론이 출력 토큰을 소진해 응답 10건 중 9건이
`length`로 종료됐다. 본 실험에서는 Solar 요청에 `reasoning_effort: low`를 지정했고, 10회
모두 별도 추론 출력 없이 `stop`으로 정상 종료됐다. 따라서 아래 평가는 추론 제어를 적용한
최종 10회 실행만을 대상으로 한다.

## 평가 기준

이번 실험은 다음 항목을 기준으로 평가했다.

1. API 호출과 응답이 오류 없이 정상 종료되는가
2. 동일한 질문과 근거에서 최종 판정이 일관되는가
3. 상업적 이용 절차, 제3자 권리, 재배포 제한, 출처표시, 기관 확인 등 핵심 조건을 설명하는가
4. 입력으로 제공한 `E01`~`E05`만 직접 근거로 인용하는가
5. 결론, 직접 근거, 실제 조치의 요구된 구조로 답변하는가

이번 파일럿에는 사람이 검증한 법률 자문 수준의 단일 정답문 또는 판정 gold가 없다.
따라서 10회 판정이 일치했다는 사실과 그 판정이 법률적으로 최종 정답이라는 평가는
구분해야 한다. 본 보고서의 정량 결과는 반복 안정성과 입력 근거 충실성을 중심으로 한다.

## 관찰된 실패 유형

### 1. 존재하지 않는 근거 ID 생성

가장 명확하게 확인된 오류다. 모델은 모든 응답에서 실제 근거 `E01`~`E05`를 사용했지만,
3개 응답에서는 여기에 존재하지 않는 ID를 추가했다. 이는 결론의 방향과 별개로 답변의
감사 가능성과 신뢰도를 훼손한다. 공공데이터 이용조건을 안내하는 서비스에서는 사용자가
원문을 추적할 수 있어야 하므로, 근거 식별자 오류를 단순한 표기 문제로 취급할 수 없다.

다만 이 오류는 입력의 허용 ID 목록과 출력 ID를 대조하면 기계적으로 탐지할 수 있다.
따라서 곧바로 SFT 필요성으로 연결하기보다 생성 제약, 구조화 출력, 후처리 검증 및 재요청을
먼저 비교하는 것이 적절하다.

### 2. 판정과 조건 표현의 편차

10회 모두 최종 판정은 같았지만 부가 표현에는 차이가 있었다. 일부 응답은 `기관 확인
필요`를 판정에 병기했고, 일부는 `조건부 이용 가능`을 단독으로 제시한 뒤 본문에서 별도
확인 필요성을 설명했다. 또한 사용 데이터의 기업 제공을 재배포, 권리 양도, 결과물 이용
중 어느 관점에서 강조하는지도 달랐다.

현재 수준의 편차가 사용자 경험에 문제가 되는지는 서비스 정책에 따라 결정해야 한다.
판정 레이블 하나만 허용해야 한다면 출력 스키마와 후처리로 먼저 통제할 수 있다.

### 3. 질문 속 `사용 데이터`의 의미 불확실성

질문의 `그 사용 데이터`는 원천 데이터를 가공한 결과물, AI 학습 데이터, 서비스 이용 로그,
개인정보가 포함된 고객 행동 데이터 등으로 해석될 수 있다. 모델은 대체로 이 불확실성을
인식하고 기관 확인이 필요하다고 안내했지만, 응답마다 가정한 데이터의 성격이 조금씩
달랐다.

이는 모델 오류만이 아니라 질문과 근거의 정보 부족에서 발생한 문제다. 실제 서비스에서는
데이터 유형에 따라 판정이 달라지는 핵심 질문을 먼저 정의하거나, 유형별 조건부 답변을
제공하도록 대화 정책을 설계해야 한다.

### 4. 법률적 정답 검증의 부재

반복 결과만으로 10개의 결론이 모두 법률적으로 옳다고 판단할 수는 없다. 현재 근거 청크가
질문에 필요한 모든 최신 규정, 개인정보 이슈, 제3자 저작물 조건을 포함하는지도 별도
검증하지 않았다. 모델의 일관성은 확인됐지만 정확성은 법률·정책 담당자가 만든 gold와
대조해야 한다.

## SFT로 해결 가능한 범위

### SFT 적합도가 상대적으로 높은 문제

- 지정된 판정 레이블 중 하나만 선택하기
- 결론, 직접 근거, 실제 조치의 고정된 순서와 형식을 유지하기
- 입력에 존재하는 근거 ID만 복사해 인용하기
- 근거에서 확인된 사실과 모델의 해석을 분리하기
- 근거가 부족하면 허용 여부를 단정하지 않고 기관 확인 필요성을 표시하기
- 데이터 유형에 따라 판정을 바꾸는 핵심 조건을 일관되게 설명하기

이 항목들은 반복 가능한 출력 행동이므로, 충분히 다양하고 검수된 학습 사례가 있다면
SFT로 개선될 가능성이 있다. 그러나 이번 실험에서는 형식과 판정이 이미 대체로 안정적이고,
확인된 핵심 오류도 기계적으로 검출 가능하다. 따라서 `개선 가능성`과 `SFT가 가장 경제적인
해결책`이라는 판단은 구분해야 한다.

### SFT만으로 해결을 장담하기 어려운 문제

- 최신 법령과 데이터별 이용조건을 계속 최신 상태로 유지하기
- RAG 검색 단계에서 누락된 근거를 복구하기
- 잘못 청킹되거나 문맥이 소실된 규정을 정확히 해석하기
- 개인정보, 제3자 저작권 등 입력에 없는 사실을 확인하기
- 법률·정책 담당자의 최종 판단을 대체하기
- 새로운 기관과 새로운 이용규약에 정확하게 일반화하기

최신 규정과 데이터별 조건은 RAG가 담당해야 하며, SFT는 제공된 근거를 해석하고 인용하는
행동을 교정하는 용도로 한정하는 것이 적합하다.

## 다음 실험 제안

SFT 데이터 제작 전에 아래 순서로 프롬프트 방식의 한계와 오류 원인을 분리하는 것이 좋다.

1. 출력에서 사용할 수 있는 근거 ID를 `E01`~`E05`로 명시하고 동일 사례를 다시 실행한다.
2. JSON Schema 등 구조화 출력을 적용해 판정 레이블과 근거 ID를 제한한다.
3. 출력된 근거 ID를 입력 목록과 자동 대조하고, 잘못된 ID가 있으면 1회 재요청한다.
4. 같은 데이터에 대한 질문 표현과 사용 목적을 바꾼 변형 사례를 평가한다.
5. 다른 기관, 다른 공공데이터, 다른 이용조건을 포함한 사례로 평가셋을 확장한다.
6. 법률·정책 담당자가 사례별 판정, 직접 근거, 필수 조치를 검수해 gold를 만든다.
7. 저비용 통제 적용 후에도 남는 오류를 모아 SFT 대상 행동으로 선정한다.

비교할 최소 실험군은 다음과 같다.

| 실험군 | 방식 | 목적 |
|---|---|---|
| A | 현재 프롬프트 + RAG 근거 | 현재 baseline 재현 |
| B | 근거 ID 제약 프롬프트 | 프롬프트 보완 효과 측정 |
| C | 구조화 출력 + ID 검증·재요청 | 기계적 통제 효과 측정 |
| D | C와 동일한 입력·검증 + SFT 모델 | SFT의 순수 추가 효과 측정 |

이 비교를 통해 SFT 없이도 목표 오류율을 달성할 수 있는지, SFT가 실제로 근거 충실성과
판정 정확도에 추가적인 개선을 주는지를 구분할 수 있다.

## SFT 데이터 설계 시 주의점

- 현재 한 사례를 10회 반복한 결과를 서로 다른 10개 학습 사례로 취급하지 않는다.
- 기관, 데이터 유형, 라이선스, 상업적 이용 목적, 재배포 방식이 다양한 사례를 확보한다.
- 질문의 정보가 충분한 사례와 추가 정보가 필요한 사례를 모두 포함한다.
- gold에는 최종 판정, 사용 가능한 근거 ID, 원문 조항, 적용 이유, 필수 조치를 사람이
  검증하여 기록한다.
- 존재하지 않는 근거를 인용한 답변, 근거보다 강한 결론을 낸 답변, 최신성이 확인되지 않은
  답변을 명시적인 반례로 포함한다.
- 동일 기관이나 동일 규정의 유사 문장이 학습·검증·시험 데이터에 중복되지 않도록 분할한다.
- 평가는 문장 유사도보다 판정 정확도, 근거 ID 유효성, 조항 인용 정확도, 필수 조건 recall,
  과잉 단정 비율을 우선한다.

## 기획 세션에서 결정할 사항

1. 서비스가 답변할 `사용 데이터`의 범위를 원천 데이터, 가공 결과물, 학습 데이터, 이용
   로그 중 어디까지로 정의할지 결정한다.
2. 판정 레이블을 반드시 하나만 선택하게 할지, `조건부 이용 가능 + 기관 확인 필요` 같은
   복합 상태를 허용할지 결정한다.
3. 근거 ID 오류를 허용하지 않기 위한 구조화 출력과 후처리 검증을 기본 아키텍처에 포함할지
   결정한다.
4. 법률·정책 담당자가 검수할 평가 사례 수와 데이터 유형별 최소 표본을 정한다.
5. 프롬프트·검증 방식의 목표 오류율과 SFT 착수 조건을 사전에 정한다.
6. SFT 도입 시 최신 지식 학습이 아니라 근거 충실성 및 불확실성 처리 행동 개선을 목표로
   명시할지 결정한다.
