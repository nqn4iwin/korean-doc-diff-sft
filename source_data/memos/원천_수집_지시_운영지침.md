# 원천 수집 지시 — 기관 운영지침 5쌍

수집을 맡은 사람이나 에이전트에게 **그대로 넘기는 문서**다. 저장소 사정을 몰라도 읽을 수 있게 썼다.
2026-08-18에 이 방식으로 산업기술혁신사업 공통 운영요령 1쌍을 실제로 받아 보고 쓴 것이다.

---

## 0. 제일 중요한 것 — 당신이 판단하지 않는다

**쓸 만한 pair인지는 스크립트가 정한다.** 당신은 후보를 찾아 스크립트에 넣고, 스크립트가
`합격`이라고 한 것만 남기면 된다. 유사도가 적당한지, 변경이 충분한지 **눈으로 보고 정하지 말 것.**
이 판단은 이미 25쌍에서 실측해 코드에 박혀 있다.

당신이 할 일은 셋뿐이다.

1. 같은 문서의 앞뒤 판본 번호 두 개를 찾는다
2. 스크립트를 돌린다
3. `합격`이면 등록하고, `반려`면 다른 판본 조합으로 다시 1번

---

## 1. 무엇을 찾는가

**국가법령정보센터(law.go.kr)에 올라온 행정규칙 중, 연구개발사업의 집행 절차를 정하는
운영요령·운영규정·사업시행지침의 서로 다른 두 판본.**

목표는 **5쌍**이다. 아래는 이미 가지고 있는 것이라 **다시 받지 말 것.**

| 이미 있음 | 기관 |
| --- | --- |
| 산업기술혁신사업 공통 운영요령 | 산업통상자원부 |
| 중소기업기술개발 지원사업 운영요령 | 중소벤처기업부 |
| 지역산업지원사업 공통운영요령 | 산업통상자원부 |
| 해양수산 연구개발사업 운영규정 | 해양수산부 |
| 팁스(TIPS) 총괄 운영지침 | 중소벤처기업부 |

**되도록 서로 다른 부처에서 가져온다.** 한 부처의 문서 다섯 개보다 다섯 부처의 문서 하나씩이 낫다.
찾아볼 만한 이름의 꼴은 이렇다.

- `○○사업 운영요령` · `○○ 연구개발사업 운영규정` · `○○사업 관리규정`
- `○○사업 시행지침` · `○○ 연구개발사업 처리규정`

**범위 밖인 것** — 법률·시행령·시행규칙(법령), 자치법규(조례·규칙), 일반 규범 성격의 행정규칙.
연구개발·지원사업의 **집행 절차**를 정하는 것만 해당한다.

---

## 2. 판본 번호(`admRulSeq`) 찾기 — 여기가 제일 까다롭다

국가법령정보센터는 **같은 문서의 판본마다 다른 번호**를 준다. 그 번호가 `admRulSeq`다.
그래서 **pair 하나 = 같은 제명의 서로 다른 `admRulSeq` 두 개**다.

**사이트의 「연혁」 탭은 자바스크립트로 채워져서 주소만으로는 목록이 안 나온다.** 페이지를
그냥 가져오면 지금 판본 하나만 보인다. 그래서 **웹 검색으로 찾는다.** 2026-08-18에 통한 방법이다.

검색어를 이렇게 쓴다.

```
"<문서 제명>" 국가법령정보센터 행정규칙 일부개정 <연도>
"<문서 제명>" admRulSeq
```

검색 결과의 링크 주소 안에 `admRulSeq=2100000208247` 같은 숫자가 들어 있다. **그 숫자를 모은다.**
한 번 검색에 두세 판본이 한꺼번에 나오는 경우가 많다.

번호를 찾았으면 그 판본이 **언제 것인지 확인한다.** 아래 주소를 열면 본문 맨 위에 시행일과
고시 번호가 있다.

```
https://www.law.go.kr/LSW/admRulLsInfoR.do?admRulSeq=<번호>&joTpYn=Y&languageType=KO&chrClsCd=010202
```

**주소를 정확히 이 꼴로 쓸 것.** `admRulLsInfoP.do`(가운데가 `P`)는 목록 화면이라 조문이 안 들어
있고, `admRulLsInfoR.do`(`R`)라야 본문 전체가 나온다.

---

## 3. 어느 두 판본을 짝지을 것인가

**간격이 3~4년이면 대체로 적당하다.** 다만 연수보다 중요한 것이 하나 있다.

> **제도가 용어를 일괄로 갈아치운 시점을 사이에 두지 않는다.**

2026-08-18에 산업기술혁신사업 공통 운영요령을 2020년판 ↔ 2024년판으로 잡았다가 반려했다.
그 사이에 **국가연구개발혁신법(2021년 1월 시행)**이 끼어 있어서, 문서 전체의 법정 용어가
한꺼번에 바뀌어 있었다.

    과제      -> 연구개발과제     224회
    전담기관  -> 전문기관         131회
    사업      -> 연구개발          55회

변경 블록이 470개나 나왔지만 **내용은 명칭 변경 하나뿐**이라 쓸 수 없었다. 같은 문서를
혁신법 이후끼리(2022년판 ↔ 2024년판)로 다시 잡으니 정상이었다.

**연구개발 분야에서는 2021년 1월을 특히 조심한다.** 그 전 판본과 그 후 판본을 짝지으면
거의 확실히 반려된다. 다른 분야에도 비슷한 시점이 있을 수 있다.

**걱정할 필요는 없다 — 스크립트가 이것을 잡는다.** 반려되면 간격을 좁혀 다시 고르면 된다.

## 4. 스크립트 돌리기

저장소 맨 위 폴더에서 실행한다. 인자는 **이전판 번호, 이후판 번호** 순이다.

```bash
python3 source_data/crawlers/check_candidate.py <이전판 admRulSeq> <이후판 admRulSeq>
```

예시 (실제로 합격한 조합이다):

```bash
python3 source_data/crawlers/check_candidate.py 2100000208247 2100000251982
```

끝에 이렇게 나온다.

```
==============================================================
  유사도            0.6562   (하한 0.55)
  실질 변경         159블록 / 141묶음
  최다 치환         '' -> ''  18회
  집중도            13%   (상한 40%, 묶음 20개 이상일 때만 본다)
==============================================================

판정: **합격**. `collect_guideline_pairs.py`의 `PAIRS`에 넣어도 된다.
```

**`판정: 합격`이면 통과, `판정: 반려`면 탈락이다.** 반려 사유가 함께 나오고, 사유마다
무엇을 고쳐야 하는지도 적혀 있다.

`[경고]`와 `[참고]`는 탈락이 아니다. **다만 `[경고]`는 무시하라는 뜻도 아니다.**
2026-08-18에 이 문장이 "없으면 그대로 써도 된다"로 적혀 있어서, 수집자가 변경이 열 몇
묶음뿐인 작은 쌍 다섯 개를 그대로 통과시켰다. 지금은 수량 관련 문구가 판정에 안 쓰이는
`[참고]`로 내려갔고, `[경고]`는 중복 허용처럼 **사람이 한 번 확인해야 하는 것**에만 붙는다.

이 스크립트는 `data/candidates/`에만 쓴다. **떨어진 후보가 원천 폴더를 더럽히지 않는다.**

## 5. 합격한 것을 등록하기

`source_data/crawlers/collect_guideline_pairs.py`를 열면 맨 위에 `PAIRS = [...]` 목록이 있다.
그 목록 **맨 끝에** 아래 틀을 채워 넣는다.

```python
    {
        "directory": "<기관약칭>_<주제>_pair",       # 예: motie_industrial_tech_guideline_pair
        "case_id": "<기관약칭>-<주제>-<이전연도>__<이후연도>",
        "issuer": "<발행 부처 이름>",
        "series": "<문서 제명 그대로>",              # 본문에 나오는 이름과 정확히 같아야 한다
        "before": {
            "file": "before_<연도>.html",
            "date": "<시행일 YYYY-MM-DD>",
            "number": "<고시 또는 훈령 번호>",
            "page_url": "https://www.law.go.kr/LSW/admRulLsInfoP.do?admRulSeq=<이전판 번호>",
            "file_url": "https://www.law.go.kr/LSW/admRulLsInfoR.do?admRulSeq=<이전판 번호>&joTpYn=Y&languageType=KO&chrClsCd=010202",
        },
        "after": {
            "file": "after_<연도>.html",
            "date": "<시행일 YYYY-MM-DD>",
            "number": "<고시 또는 훈령 번호>",
            "page_url": "https://www.law.go.kr/LSW/admRulLsInfoP.do?admRulSeq=<이후판 번호>",
            "file_url": "https://www.law.go.kr/LSW/admRulLsInfoR.do?admRulSeq=<이후판 번호>&joTpYn=Y&languageType=KO&chrClsCd=010202",
        },
    },
```

`series`는 **문서 본문에 나오는 제명과 글자가 같아야 한다.** 다르면 수집 스크립트가
"제명이 본문에 없다"며 멈춘다. 이것은 엉뚱한 문서를 받았는지 확인하는 장치다.

넣었으면 그 디렉터리 이름만 인자로 주고 돌린다.

```bash
python3 source_data/crawlers/collect_guideline_pairs.py <directory 값>
```

`saved: ...classify.json`이 찍히면 끝난 것이다. `data/raw_collection/<directory>/`에
원문·추출본·`manifest.json`이 생긴다.

## 7. 하지 말 것

- **`data/raw_collection/`에 손으로 파일을 넣지 않는다.** 반드시 수집 스크립트를 거친다.
  해시·MIME·추출 결과가 `manifest.json`에 남아야 한다.
- **`training_data/` 아래를 건드리지 않는다.** 이 일은 원천 수집이다.
- **로그인·결제·다운로드 제한이 걸린 문서는 건너뛴다.** 우회하지 않는다.
- **PDF와 구형 HWP는 건너뛴다.** 둘 다 조항 단위로 자를 수 없다. 국가법령정보센터 본문
  HTML을 쓰는 것이 이 방식의 요점이다.
- **판단이 필요하다고 느끼면 멈추고 물어본다.** 애매한 것을 통과시키는 것보다 낫다.
