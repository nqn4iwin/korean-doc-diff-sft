# 원천 수집 지시 — 표준약관 · 지원사업 공고

수집을 맡은 사람이나 에이전트에게 **그대로 넘기는 문서**다. 저장소 사정을 몰라도 읽을 수
있게 썼다. 2026-08-18에 이 방식으로 기관 운영지침 5쌍을 실제로 받아 보고, 그때 겪은 실패를
반영해 다시 쓴 것이다.

---

## 0. 제일 먼저 알아야 할 세 가지

### (1) 당신이 판단하지 않는다

**쓸 만한 pair인지는 스크립트가 정한다.** 당신은 후보를 찾아 스크립트에 넣고, 스크립트가
`합격`이라고 한 것만 남기면 된다. 유사도가 적당한지, 변경이 충분한지 **눈으로 보고 정하지
말 것.** 이 판단은 이미 25쌍에서 실측해 코드에 박혀 있다.

### (2) 이미 가진 문서 목록을 외우지 않는다

**중복은 스크립트가 막는다.** `check_candidate.py`는 후보를 `data/raw_collection/` 아래 이미
가진 문서 전부와 대조하고, 같은 문서면 그 자리에서 반려한다. 아래 3절에 목록이 있지만 그것은
당신이 헛수고를 덜라고 적어 둔 참고일 뿐이고, **실제 차단은 코드가 한다.** 목록을 잘못 읽어
같은 것을 다시 받아도 등록까지 가지 않는다.

### (3) PDF와 구형 HWP는 아예 쓸 수 없다

이 저장소는 문서를 **문단 단위로 잘라서** 앞뒤 판본을 맞춰 본다. PDF는 인쇄된 지면을 좌표
위의 글자로 적을 뿐이라 문단이라는 개념이 없다. 구형 HWP(한/글 바이너리, `.hwp`)는 열려면
한컴오피스 변환이 필요한데 그건 사람 손이 드는 일이다.

**둘 다 스크립트가 첫 바이트를 보고 즉시 반려한다.** 확장자를 `.hwpx`로 적어 놔도 내용이
PDF면 걸린다. 쓸 수 있는 것은 **HWPX(`.hwpx`)와 HTML** 둘뿐이다.

당신이 할 일은 셋뿐이다.

1. 같은 문서의 앞뒤 판본 두 개를 찾는다
2. 스크립트를 돌린다
3. `합격`이면 등록하고, `반려`면 다른 조합으로 다시 1번

## 1. 무엇을 몇 쌍 찾는가

이번에 노리는 것은 **두 종류**다.

| 우선 | 종류 | 지금 | 이번 목표 | 왜 |
| ---: | --- | ---: | --- | --- |
| **1** | 지원사업 공고 · 정정공고 | 3쌍 | **3쌍 이상 더, 많을수록 좋다. 반드시 중기부가 아닌 부처에서** | 문서가 길어서 값이 크다 |
| **2** | 표준약관 | 5쌍 | **공정위 밖에서 찾을 수 있으면. 없으면 없다고 보고** | 업종 다양성 |

**공고 3쌍은 다 중소벤처기업부다.** 그래서 이번에 중기부에서 더 받으면 얻는 것이 거의
없다. 다른 부처 것이라야 한다.

**공고를 먼저 한다.** 공고 한 쌍은 문서가 700줄이 넘어서, 바뀐 곳은 두세 군데뿐이어도
문서 자체가 뒤에 쓰일 재료가 된다. 표준약관은 100줄 안팎이라 그 값이 작다.

**바뀐 곳이 적다고 버리지 않는다.** 이 저장소가 원천에서 뽑는 것은 바뀐 부분만이 아니라
문서의 모든 조항이다. 그래서 700줄짜리 공고는 바뀐 곳이 세 군데뿐이어도 값이 크고,
100줄짜리 약관은 바뀐 곳이 열 군데여도 값이 작다. **길이를 본다.**

숫자를 못 채워도 된다. **조건에 안 맞는 것을 맞는 것처럼 보내는 쪽이, 적게 보내는 것보다
훨씬 손해가 크다.** 검증에 드는 품이 더 든다.

## 2. 어떤 두 판본이라야 하는가

**같은 문서의 서로 다른 두 시점 판본**이어야 한다. 닮은 두 문서가 아니다. A기관 공고와
B기관 공고는 아무리 비슷해도 쓸 수 없다.

같은 계열임이 **문서 자체로** 증명돼야 한다. 아래 중 하나 이상이 있어야 하고, 무엇으로
증명했는지 보고에 적는다.

- 두 문서가 **같은 고유번호**를 달고 있다 (예: 표준약관 제10012호가 개정 후에도 유지)
- 새 문서가 **옛 문서를 명시적으로 가리킨다** (예: "공고 제2026-40호를 수정한 공고입니다")
- 사이트가 **이전 판본 링크를 스스로 보존**한다

로그인·결제·기관 내부망이 필요하면 탈락이다. 공식 발행처가 올린 것이라야 하고 블로그나
뉴스 재게시본은 안 된다. **우회하지 않는다.**

## 5. 지원사업 공고 — 여기에 품을 들인다

### 무엇을 찾는가

부처와 공공기관은 사업 공고를 낸 뒤 내용을 고칠 때 **정정공고·수정공고**를 다시 올린다.
수정공고 본문이 **원공고의 공고번호와 공고일을 그대로 인용**하기 때문에 같은 계열임을
증명하기가 쉽다. 이미 받아 둔 한 쌍이 이렇게 생겼다.

```
이전판  중소벤처기업부 공고 제2026-40호  (2026-01-26)
이후판  중소벤처기업부 공고 제2026-188호 (2026-03-19)
근거    "※ 본 공고는 「2026년 팁스(TIPS) 창업기업 지원계획 공고」(공고 제 2026-40호,
        2026년 1월 26일)를 다음과 같이 수정한 공고입니다."
```

**이 문장 같은 것을 찾는 일이다.** 제목이 비슷한 것으로는 안 되고, 본문 안에서 앞 공고를
가리키는 문구가 있어야 한다.

### 중기부 공고 두 쌍은 이미 받았다 — 다시 받지 말 것

2026-08-18에 아래 두 쌍을 검증하고 실제로 받아 등록까지 마쳤다. **손대지 않는다.**

| 폴더 | 공고 | 유사도 | 실질 변경 |
| --- | --- | ---: | --- |
| `mss_modoo_startup_notice_pair` | 「모두의 창업 프로젝트」 제2026-208호 → 제2026-275호 | 0.9818 | 17블록/12묶음 |
| `mss_innovation_voucher_notice_pair` | 중소기업 혁신바우처(채용지원) 제2026-280호 → 제2026-317호 | 0.9613 | 7블록/7묶음 |

**이것까지 해서 공고 3쌍이 전부 중소벤처기업부다.** 그래서 이번에는 중기부 게시판을
보지 않는다. 다른 부처에서 가져와야 유형 다양성이 생긴다.

### 확인해 볼 만한 것 하나

**2026년 수출지원기반활용사업 참여기업 2차 모집** — 중기부 게시판에 수정공고가 있는 것을
확인했다(원공고 게시글 `bcIdx=1067310`, 첨부는 HWPX). 다만 **이것도 중기부라 우선순위가
낮다.** 다른 부처를 다 뒤졌는데 세 쌍이 안 나올 때만 본다.

### 게시글에서 첨부 주소를 뽑는 법

부처 게시판은 대개 게시글 HTML 안에 첨부 다운로드 링크가 그대로 들어 있다. 브라우저로
일일이 누르지 말고 이렇게 뽑는다. 아래는 중기부 예시이고, **다른 부처는 링크 경로가
다르므로 정규식의 `/common/board/Download\.do` 부분을 그 사이트에 맞게 바꾼다.**

```bash
python3 - <<'EOF'
import urllib.request, re, html
u = "https://www.mss.go.kr/site/smba/ex/bbs/View.do?bcIdx=<번호>&cbIdx=310"
b = urllib.request.urlopen(urllib.request.Request(u, headers={"User-Agent": "collect"}), timeout=40).read().decode("utf-8", "replace")
for l in dict.fromkeys(re.findall(r'(/common/board/Download\.do\?[^"\'<>\s]+)', b)):
    print("https://www.mss.go.kr" + html.unescape(l))
EOF
```

**`.pdf`로 끝나는 링크는 무시하고 `.hwpx`로 끝나는 것만 쓴다.** 중기부 공고는 같은
내용을 HWPX와 PDF 두 벌로 올리는 일이 많아서, 목록에 둘 다 나오는 것이 정상이다.

### 어디를 보는가

- **부처 공고 게시판** — 과학기술정보통신부, 산업통상자원부, 고용노동부, 문화체육관광부,
  농림축산식품부, 환경부, 국토교통부 등. 중소벤처기업부는 이미 한 쌍 받았으니 **다른
  부처를 먼저 본다.**
- **K-Startup** (`https://www.k-startup.go.kr/web/contents/bizpbanc-ongoing.do`) — 창업지원
  공고가 모여 있다. 이미 받은 쌍의 이후판이 여기서 나왔다.
- **전문기관 공고** — 한국산업기술기획평가원, 정보통신기획평가원, 한국콘텐츠진흥원,
  한국연구재단 등의 사업공고 게시판.

검색어는 이런 꼴로 쓴다.

```
"수정한 공고입니다" 2026 공고 hwpx
"정정공고" <부처 이름> 사업 공고 2025
<사업 이름> 공고 제2025- 수정공고
```

**서로 다른 부처에서 한 쌍씩** 가져오는 것이 한 부처에서 세 쌍 가져오는 것보다 낫다.

### 주의할 점 둘

**첫째, 두 판본이 다른 사이트에 있어도 된다.** 이미 받은 쌍은 이전판이 중기부 홈페이지,
이후판이 K-Startup에 있다. 발행처가 공식이기만 하면 된다.

**둘째, 파일 이름을 근거로 삼지 않는다.** 이미 받은 쌍의 이전판은 파일 이름에 `(수정)`이
들어 있는데 본문 머리글은 제2026-40호, 즉 원공고다. **판단은 본문 머리글로 한다.**

## 6. 스크립트 돌리기

저장소 맨 위 폴더에서 실행한다. 인자는 **이전판, 이후판** 순이고 세 가지 꼴을 다 받는다.

```bash
# (1) 첨부파일 주소 두 개 — 표준약관, 부처 공고에 쓴다
python3 source_data/crawlers/check_candidate.py \
    "https://www.ftc.go.kr/www/downloadBbsFile.do?atchmnflNo=14856" \
    "https://www.ftc.go.kr/www/downloadBbsFile.do?atchmnflNo=14866" \
    --name ftc_10012_deposit

# (2) 국가법령정보센터 행정규칙이면 판본번호(admRulSeq) 두 개
python3 source_data/crawlers/check_candidate.py 2100000208247 2100000251982

# (3) 이미 받아 둔 파일 두 개
python3 source_data/crawlers/check_candidate.py before.hwpx after.hwpx
```

`--name`은 후보를 담을 폴더 이름이다. 안 주면 주소에서 알아서 만든다.

### 나오는 것을 읽는 법

위 (1)번을 실제로 돌리면 이렇게 나온다.

```
==============================================================
  유사도            0.9495   (하한 0.55)
  실질 변경         3블록 / 3묶음
  최다 치환         '' -> ''  5회
  집중도            보지 않는다 (묶음이 3개뿐, 20개 이상일 때만 본다)
  중복 검사        before  최다 0.00  ftc_game_terms   (상한 0.55)
                   after   최다 0.00  ftc_game_terms   (상한 0.55)
==============================================================

[참고] 실질 변경이 3묶음이다. 판정에는 안 쓴다 (...)

판정: **합격**. `collect_guideline_pairs.py`의 `PAIRS`에 넣어도 된다.
```

머리말이 세 가지다. **뜻이 다르니 구별해서 읽는다.**

| 머리말 | 뜻 | 할 일 |
| --- | --- | --- |
| `[반려]` | 탈락이다 | 사유가 같이 나온다. 다른 조합으로 다시 |
| `[경고]` | 통과했지만 **사람이 한 번 확인해야 한다** | 무시하지 말 것. 아래 설명대로 확인 |
| `[참고]` | 판정에 안 쓰이는 정보다 | 읽고 넘어가면 된다 |

**`[참고]`로 나오는 "실질 변경이 N묶음뿐이다"는 탈락 사유가 아니다.** 원천 하나에서
바뀐 곳이 한 군데뿐이어도 원천 한 쌍으로 센다. 표준약관은 원래 한 쌍에서 1~4건, 정정공고는
3건 정도밖에 안 나온다. 여기에 하한을 두면 이번에 노리는 두 종류가 통째로 걸린다.

> 2026-08-18에 이 문구가 `[경고]`였고 지시문에 "경고는 무시해도 된다"고 적혀 있었다.
> 그래서 수집자가 변경이 열 몇 묶음뿐인 작은 쌍 다섯 개를 그대로 통과시켰다. 그래서
> 지금은 아예 `[참고]`로 내렸다. **`[경고]`는 이제 무시하라는 뜻이 아니다.**

### 중복 검사에서 반려됐을 때

이렇게 나온다.

```
[반려] before 쪽이 **이미 가진 문서**다. `ftc_gift_certificate_terms/2024_standard_terms.hwpx`과
100% 겹친다(상한 55%). (...) 같은 계열에서 판본 조합을 하나 더 받는 것이 목적이었다면
`--allow-series ftc_gift_certificate_terms`를 붙여 다시 돌린다.
```

**기본은 다른 계열을 고르는 것이다.** 남남인 문서끼리는 같은 장르여도 32%를 넘은 적이
없으므로, 55%를 넘었다면 같은 문서로 봐도 된다.

일부러 **같은 계열의 다른 판본 조합**을 하나 더 받으려는 경우에만 `--allow-series`를 붙인다.
아래는 실제로 그렇게 받은 신유형 상품권 2024→2025의 명령이다(이미 받았으니 다시 돌릴
필요는 없고, 형태만 보면 된다).

```bash
python3 source_data/crawlers/check_candidate.py \
    "https://www.ftc.go.kr/www/downloadBbsFile.do?atchmnflNo=14863" \
    "https://www.ftc.go.kr/www/downloadBbsFile.do?atchmnflNo=51574" \
    --name ftc_10073_gift_2024_2025 \
    --allow-series ftc_gift_certificate_terms
```

**한 계열에서 최대 3쌍이다.** 같은 문서가 열 번 변한 것은 열 개의 사례가 아니라 하나의
사례에 가깝다.

이 스크립트는 `data/candidates/`에만 쓴다. **떨어진 후보가 원천 폴더를 더럽히지 않는다.**

## 7. 합격한 것을 등록하기

`source_data/crawlers/collect_guideline_pairs.py`를 열면 맨 위에 `PAIRS = [...]` 목록이 있다.
**이름은 운영지침이지만 주소만 있으면 어떤 원천이든 등록한다.** 그 목록 맨 끝에 아래 틀을
채워 넣는다.

```python
    {
        "directory": "<기관약칭>_<주제>_pair",   # 예: ftc_deposit_terms_pair
        "case_id": "<기관약칭>-<주제>-<이전>__<이후>",
        "issuer": "<발행 기관 이름>",
        "series": "<문서 제명 그대로>",          # 본문에 나오는 이름과 글자가 같아야 한다
        "source_class": "표준약관",              # 또는 "지원사업 공고·정정공고"
        "match_evidence": {
            "type": "same_standard_terms_number",   # 또는 explicit_prior_notice_citation
            "value": "제10012호",                   # 공고면 인용 문장을 그대로 넣는다
        },
        "scope_note": "<이 원천을 왜 받았는지 한 줄>",
        "before": {
            "file": "before_2019.hwpx",          # 확장자는 .hwpx 또는 .html 만
            "date": "<개정일 또는 공고일 YYYY-MM-DD>",
            "number": "<표준약관 번호 또는 공고 번호>",
            "page_url": "<사람이 보는 게시물 주소>",
            "file_url": "<첨부파일 내려받기 주소>",
        },
        "after": {
            "file": "after_2024.hwpx",
            "date": "...",
            "number": "...",
            "page_url": "...",
            "file_url": "...",
        },
    },
```

`series`는 **문서 본문에 나오는 제명과 글자가 같아야 한다.** 다르면 수집 스크립트가
"제명이 본문에 없다"며 멈춘다. 엉뚱한 문서를 받았는지 확인하는 장치다.

넣었으면 그 `directory` 값만 인자로 주고 돌린다.

```bash
python3 source_data/crawlers/collect_guideline_pairs.py <directory 값>
```

`data/raw_collection/<directory>/`에 원문·추출본·`classify.json`·`manifest.json`이 생기면
끝난 것이다.

## 9. 하지 말 것

- **`data/raw_collection/`에 손으로 파일을 넣지 않는다.** 반드시 수집 스크립트를 거친다.
  해시·MIME·추출 결과가 `manifest.json`에 남아야 한다.
- **`manifest.json`을 손으로 고치지 않는다.** 필요한 값은 `PAIRS` 항목에 넣으면 스크립트가
  써 준다.
- **`training_data/` 아래를 건드리지 않는다.** 이 일은 원천 수집이다.
- **git 명령을 쓰지 않는다.** 커밋은 저장소 주인이 직접 한다.
- **로그인·결제·다운로드 제한이 걸린 문서는 건너뛴다.** 우회하지 않는다.
- **PDF와 구형 HWP는 건너뛴다.** 변환해서 쓰려고 하지 않는다.
- **판단이 필요하다고 느끼면 멈추고 물어본다.** 애매한 것을 통과시키는 것보다 낫다.
