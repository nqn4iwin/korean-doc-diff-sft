# 사전규격–입찰공고 변경 pair 탐색 메모

## 작성 목적

`prompt_test`의 02번 Solar 파일럿에 사용할 단일 사례를 찾는 과정에서 확인한
수율과 난점을 기록한다. 여기서 목표 사례는 다음 조건을 모두 만족하는
사전규격–입찰공고 pair다.

- 동일 과제라는 연결 근거가 명확함
- IT·AI와 관련된 과제임
- 양쪽에 비교 가능한 제안요청서·과업지시서·규격서가 존재함
- 공백, 서식, 파일 메타데이터 또는 법조문 한 글자만 다른 사례가 아님
- 범위, 일정, 기한, 산출물, 평가기준 등에서 의미 있는 변화가 최소 2개 존재함

## 탐색 기간과 범위

탐색일은 2026년 7월 31일이다. API 메타데이터는 다음 공고 등록 구간을
확인했다.

### 전량 페이지 수집 구간

- 2026년 2월 9일~2월 11일
- 2026년 4월 13일~4월 15일
- 2026년 6월 15일~7월 23일
  - 6월 15~17일
  - 6월 18일~7월 5일
  - 7월 6~8일
  - 7월 9~11일
  - 7월 12~14일
  - 7월 15~17일
  - 7월 18~20일
  - 7월 21~23일

각 구간은 두 API의 `totalCount`를 먼저 확인하고 페이지당 최대 999행으로 마지막
페이지까지 수집했다. 6월 15일~7월 23일은 중간 날짜를 건너뛰지 않은 연속
범위다.

### 기존 최신 표본

- 2026년 7월 24일~7월 31일 부근의 기존 최신 표본
- 사전규격 최근 표본 1,000건
- 입찰공고 기존 시간제 표본과 999행 표본

이 최신 구간은 `totalCount` 전체를 페이지 끝까지 받은 전량 구간이 아니다.
따라서 아래 수율은 전 기간의 모집단 통계가 아니라, 전량 수집 구간과 기존 최신
표본을 중복 제거하여 합친 탐색 실적이다.

## 탐색 수율

중복 제거 기준 집계는 다음과 같다.

| 단계 | 수량 |
|---|---:|
| 사전규격 메타데이터 | 10,555건 |
| 입찰공고 메타데이터 | 28,263건 |
| 전체 메타데이터 | 38,818건 |
| 사전규격등록번호로 직접 연결된 프로젝트 | 7,130개 |
| 제목 키워드 기준 IT·AI 관련 프로젝트 | 1,402개 |
| 양쪽에 비교 문서가 있는 IT·AI 프로젝트 | 966개 |
| 변경공고이면서 양쪽 비교 문서가 있는 프로젝트 | 56개 |
| 첨부 원문을 직접 내려받아 확인한 후보 | 13개 |
| 현재 기준을 통과한 목표 pair | 1개 |

이 집계에서 입찰공고 차수는 메타데이터 레코드로 보존하되, 프로젝트 수는
`사전규격등록번호 + 입찰공고번호` 기준으로 중복을 합쳤다.

현재 목표 pair의 관측 수율은 다음과 같다.

- 전체 메타데이터 대비 `1 / 38,818`
- 직접 연결 프로젝트 대비 `1 / 7,130`
- 비교 가능한 IT·AI 프로젝트 대비 `1 / 966`
- 변경공고 비교 가능 프로젝트 대비 `1 / 56`
- 실제 첨부를 내려받아 검수한 후보 대비 `1 / 13`

키워드 필터와 일부 최신 표본이 포함된 탐색 결과이므로 이 비율을 전체 나라장터의
통계적 발생률로 일반화하면 안 된다.

## 현재 선정 사례

- 과제명: `2026 소상공인 상생협업 교육 장비 임차 및 AI 실습지원 용역`
- 사전규격등록번호: `R26BD00244326`
- 입찰공고번호: `R26BK01607991-001`
- 사전규격 PDF는 원공고 `000`의 제안요청서 PDF와 SHA-256이 동일함
- 변경공고 `001`에는 파일명에 `(수정)`이 표시된 다른 제안요청서 PDF가 게시됨

확인한 변화는 다음과 같다.

- 입찰마감: `2026-07-02 11:00`에서 `2026-07-10 14:00`으로 변경
- 서류 제출: `2026-07-02 18:00`에서 `2026-07-10 18:00`으로 변경
- AI 실습 일정: 7월 초 일정 삭제·조정 및 8월 일정 추가 예정 문구 반영

이 사례는 일정·기한 변경 검증에는 사용할 수 있다. 다만 순수한 IT 시스템 개발
과제라기보다 AI 실습지원과 교육 장비 운영 성격이 강하므로, IT 시스템 구축
도메인의 대표 사례로 일반화하기에는 약하다.

## 확인된 난점

### 1. 사전규격과 최종 제안요청서가 동일한 경우가 많음

직접 연결되고 파일명이 달라도 실제 파일 크기와 SHA-256을 확인하면 동일한
제안요청서를 재게시한 사례가 많았다. 일반공고 `000`뿐 아니라 `001`~`003`
변경공고에서도 제안요청서가 모든 차수에 걸쳐 동일한 사례가 있었다.

따라서 변경공고라는 메타데이터만으로 RFP 요구사항이 바뀌었다고 판단할 수 없다.

### 2. 변경공고의 변경 대상이 RFP가 아닐 수 있음

공고 일정, 연락처, 입찰 방식 또는 공고문만 수정되고 제안요청서·과업지시서는
그대로인 경우가 있다. `chgNtceRsn`에 변경공고라고 적혀 있어도 대응 원문을
체크섬과 본문으로 다시 확인해야 한다.

### 3. 첨부 문서 추가는 요구사항 변경의 증거가 아님

사전규격에는 RFP 한 개만 있고 입찰공고에는 평가기준·가격제안서·서약서가 추가된
사례가 있었다. 이는 입찰 단계에서 공개 문서가 늘어난 사실은 보여주지만, 해당
문서가 새로 작성됐거나 사업 요구사항이 변경됐다는 증거는 아니다.

문서 목록의 `0:1` 추가와 Requirement Atom의 `0:1` 추가를 구분해야 한다.

### 4. 바이너리 차이가 의미 변화와 일치하지 않음

HWP/HWPX는 저장 시각, 내부 메타데이터와 패키징 차이만으로 SHA-256이 달라질 수
있다. 반대로 파일명이 `(수정)`이어도 어느 부분이 달라졌는지는 본문 전체를
추출하기 전까지 알 수 없다.

선별 순서는 다음과 같아야 한다.

1. 파일 크기와 체크섬 비교
2. 정규화한 전체 텍스트 비교
3. 변경 span 확인
4. 일정·범위·의무·산출물 등 의미 필드 판정

### 5. 사전규격 API의 첨부 URL이 비어 있는 사례가 있음

IT 변경공고이면서 입찰공고 문서는 존재하지만, 사전규격 API의 첨부 URL이 빈
사례가 있었다. 사전규격등록번호로 직접 연결되더라도 양쪽 원문을 자동 확보할 수
없으면 학습·평가 pair로 사용할 수 없다.

공식 상세 페이지에서 원문을 재현 가능하게 확보하지 못하면 제외하는 편이
안전하다.

### 6. 제목 키워드 필터의 오탐이 많음

`시스템`, `데이터`, `전산`, `AI` 같은 단어만으로 필터링하면 다음 사례가 함께
잡힌다.

- 행사장 시스템 설치
- 학교명이 전산정보고인 여행 용역
- AI 제품 단순 렌탈
- AI 교육 장비 운영

IT·AI 도메인 여부는 제목 키워드 외에 과업 목적, 산출물과 요구사항 본문을 함께
검토해야 한다.

### 7. 원문 검증 비용이 메타데이터 수집 비용보다 큼

메타데이터는 페이지당 999행으로 수천 건을 적은 API 호출로 수집할 수 있다.
실제로 6월 18일~7월 5일의 사전규격 3,127건과 입찰공고 8,411건은 총 13회
호출로 전량 수집했다.

반면 유효 pair 판정에는 다음 작업이 필요하다.

- 다중 첨부 중 대응 문서 식별
- HWP/HWPX/PDF 형식 판별
- HWP의 HWPX·PDF 변환
- 전체 텍스트 추출과 정규화
- 변경 span과 의미 변화의 수동 확인

따라서 천 건 단위 메타데이터 수집은 가능하지만, 천 건 단위의 의미 있는 변경
pair 확보는 현재 관측 수율과 검수 비용상 어렵다.

### 8. PDF 페이지 매핑도 별도 비용임

이번 임시 PDF 파싱에서 전체 텍스트 블록 추출은 가능했지만, Word 변환 결과의
모든 문단에 페이지 번호를 조회하는 작업은 5분 제한을 넘겼다. 파일럿 입력에는
텍스트 블록만 사용하고, 정확한 페이지 근거가 필요해질 때 PDF 전용 파서를
별도로 검토해야 한다.

## 후속 수집 시 권장 기준

다음 탐색부터는 아래 순서를 적용한다.

1. 날짜 구간을 겹치지 않게 연속 수집
2. 사전규격등록번호로 직접 연결
3. 양쪽 첨부 URL과 대응 문서 존재 여부 확인
4. IT·AI 도메인을 제목과 과업 본문으로 이중 확인
5. 변경공고 차수가 있는 프로젝트 우선
6. 사전규격·원공고·최종 변경공고의 대응 파일 체크섬 비교
7. 전체 텍스트가 다른 후보만 변환·파싱
8. 의미 있는 변경이 최소 2개 확인된 뒤에만 파일럿 case 생성

대량 수집 단계에서는 메타데이터 수량보다 다음 수율을 별도로 보고해야 한다.

- 직접 연결률
- 양쪽 원문 확보율
- 동일 파일 제외 후 본문 변경률
- IT·AI 도메인 적합률
- 의미 변화 2개 이상 보유율
- 문서 한 pair당 다운로드·변환·검수 시간
